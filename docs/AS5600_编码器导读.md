## 0. 一句话定位

底座是 **360° 连续旋转舵机**：它只会按你给的脉宽**定速转**，**自己不知道转到哪了**
（内部电位器被改造成测速用，位置信息没了）。

AS5600 在轴端测**磁场方向**，直接把**绝对角度**告诉单片机。

> 于是底座从一个"只会转的电机"变成"真正的角度轴"。
> `0x10` 帧里的 `q1_act` 也从"我猜的"变成"测出来的"。

**它是绝对式的**：上电就知道朝哪，不需要回零、不需要撞限位开关。

## 1. 三个坐标系 —— 全篇最重要的一节

这一段没看懂，后面全是天书。

| 坐标系 | 范围 | **谁说了算** | 代码里在哪 |
|---|---|---|---|
| **原始角** raw | `0 ~ 360°` | **磁铁是随手粘上去的** | `as5600_read_deg()` 的输出 |
| **机械角** meas | `−180 ~ +180°` | 手臂自己的机械零位 | `base_read_deg()` 的输出 → `vel_tick()` 里的 `meas` |
| **目标角** tgt | `−180 ~ +180°` | 上位机 / 插补器 | `s_tgt_deg[]` |

### 换算公式

```
机械角 = wrap180( SIGN × (原始角 − ZERO) )
```

- `ZERO` = `ARM_BASE_ENC_ZERO_DEG` —— 机械零位那一刻，编码器读到多少
- `SIGN` = `ARM_BASE_ENC_SIGN` —— 机械正方向转动时，编码器读数是变大还是变小

### 为什么必须换算

**原始角是"磁铁的坐标系"，不是"手臂的坐标系"。**

打个比方：你在一个房间里随便贴了一张纸，纸上画了个 0° 刻度和一圈刻度尺。
纸贴在墙上时是歪的 —— 你读出来的"角度"跟房间的"正前方"差了一个固定角度。
`ZERO` 就是那个固定的差。

两条必须换算的理由：

1. **零点偏置**：磁铁粘在哪，AS5600 的零就在哪。它读 0° 的那一刻，手臂可能正指着墙。
   不换算 → 手臂明明朝正前方，`q1_act` 报 `213.7°` → 闭环永远在追一个偏了 213° 的目标
   → **舵机会以最大速度冲向那个假目标**。

2. **方向符号**：磁铁装反了、或者舵机齿轮反向，就会出现"原始角增大时机械角在减小"。
   不换算 → **正反馈**：误差越大推得越狠，舵机一路顶死在限位上烧掉（详见 §7）。

### `wrap180()` 又是干什么的

把任意角度绕进 `(-180, +180]`：

```c
static float wrap180(float a)   // arm_joint.c
{
  while (a >  180.0f) { a -= 360.0f; }
  while (a <= -180.0f) { a += 360.0f; }
  return a;
}
```

为什么需要：`359°` 和 `1°` 其实只差 `2°`，但直接相减得 `358°`。绕一圈之后才是 `−2°`。
**不绕，闭环会在 0°/360° 那条缝上疯狂抽搐。**

## 2. 数据流：一次控制拍的全过程

```
        磁铁（粘在转盘上，跟着转）
              ↓ 磁场方向
        ┌─────────────┐
        │  AS5600 芯片 │   I²C：PB6(SCL) / PB7(SDA)，400kHz，地址 0x36
        └─────────────┘
              ↓  12 位原始值 0~4095
      as5600_read_deg()             → 原始角 0~360°
              ↓
      base_read_deg()               → 机械角 −180~+180°   ← §5.1 讲这个
              ↓
      vel_tick() 里的 meas
              ↓
      err = wrap180(tgt − meas)
              ↓
      u = Kp × err  （以后加前馈）  → 限幅 → 死区   ← §6.2 讲这个
              ↓
      arm_set_us(joint, us_stop + u)
              ↓
      arm_pwm.c：µs → CCR
              ↓
      TIM2 → 脉宽 → 舵机转速
              ↓
      ┌──────────────────────────┐
      └──────────────────────────┘  ← 转完又回到 AS5600，闭环成立
```

**这个环每 20ms 跑一次**（`proto_app` 的 20ms 节拍里调 `arm_joint_tick()`）。

## 3. 硬件部分：三个数决定它能不能用

| 项 | 要求 | 不满足的现象 |
|---|---|---|
| **磁铁类型** | **径向充磁**（diametrically magnetized） | 读数**一动不动**（见 §8 误解 3） |
| **气隙** | 磁铁表面到芯片表面 **1~2mm**（0.5~3 可接受） | 太近饱和、太远信号弱，都是读数跳变 |
| **同轴度** | 磁铁中心 ↔ 芯片中心偏差 **≤0.5mm** | 角度误差呈正弦周期波动，怎么标都标不准 |

### 接线

| AS5600 | 接到 | 注意 |
|---|---|---|
| VCC | **3.3V** | ⚠️ **不是 5V**，这颗是纯 3.3V 器件 |
| GND | GND | 必须和主控共地 |
| SCL | `PB6`（I²C1_SCL） | |
| SDA | `PB7`（I²C1_SDA） | |

和 MPU6050 共用同一条总线。两个地址不同（AS5600 = `0x36`，MPU6050 = `0x68`），**不冲突**。
两块模块各自带 4.7kΩ 上拉，并联后约 2.35kΩ，仍在允许范围，**不用额外加电阻**。

## 4. `as5600.h` 逐条：三个 API 的"契约"

这个头文件不长，但有三句话是**设计约束**，改代码之前必须先认可它们。

### 4.1 `as5600_init()`

```c
uint8_t as5600_init(void);
/* @retval 1 = 在线；0 = 不在（没接/接线错/I2C 没配/没磁铁） */
```

**"不在线不是致命错误"** —— 这一句很重要：

> `arm_joint.c` 会据此把**底座**判为故障并让它停转，**其余三个关节照常工作**。
> 这样就算编码器临时坏了，手臂也不会整体瘫痪，更不会乱动。

### 4.2 `as5600_read_deg()`

```c
uint8_t as5600_read_deg(float *deg);
/* @retval 1 = 成功；0 = 失败 */
/* @note  失败时 **不修改** *deg */
```

**「失败时不修改 `*deg`」是一条契约，不是随手写的。**

这样调用方可以这样做：

```c
float d = 0.0f;
if (base_read_deg(&d)) { /* 用 d */ }
else                   { /* d 还是上一次的值，或者 0 —— 反正不是垃圾 */ }
```

如果失败时往里塞 `0.0f`，调用方就无法区分"真的在 0°"和"读失败了" —— 后者会让闭环
以为手臂跑到了 0° 然后猛甩回去。**这是"无声的错误"里最危险的一种。**

### 4.3 `as5600_present()`

返回缓存的在线状态，**不重复读总线**。读总线是有代价的（一次事务 ≈ 几百 µs），
不能每个控制拍都去探一次设备在不在 —— 那会白白吃掉控制周期。

## 5. `as5600.c` 逐段

### 5.1 寄存器速查（别背，用的时候查）

| 地址 | 名字 | 内容 |
|---|---|---|
| `0x0B` | STATUS | bit5 = **MD**（检测到磁铁）、bit4 = MH（磁场太强）、bit3 = ML（磁场太弱） |
| `0x0C` | RAW ANGLE 高 8 位 | **纯原始值**，没做任何处理 |
| `0x0D` | RAW ANGLE 低 4 位 | 在 bit7:4 |
| `0x0E` | **ANGLE 高 8 位** | **已应用芯片内部的 ZPOS/MPOS**（零点/量程）← 代码用这个 |
| `0x0F` | ANGLE 低 4 位 | 在 bit7:4 |

**为什么用 `0x0E`（ANGLE）而不是 `0x0C`（RAW）**：

ANGLE 会把芯片内部编程的 `ZPOS`（零点）和 `MPOS`（量程）算进去。本工程**没用**这两个寄存器
（零点在软件里用 `ARM_BASE_ENC_ZERO_DEG` 做，因为烧写芯片不可逆、换个机械结构就得重烧）。
所以两者现在数值一样 —— 但用 ANGLE 是对的：将来万一想用芯片自带零点，代码不用改。

### 5.2 为什么地址要左移一位

```c
#define AS5600_ADDR  (0x36u << 1)   /* = 0x6C */
```

I²C 的 **7 位地址**是 `0x36`。但线上传输时第 8 位要拿来当**读写位**：

| 操作 | 线上字节 |
|---|---|
| 7 位地址 | `0110110`（= 0x36） |
| 写 | `01101100` = `0x6C` |
| 读 | `01101101` = `0x6D` |

HAL 库要的是**已经左移好的 8 位地址**，读写位它自己补。所以写 `0x36 << 1`。

> 忘记左移是最常见的"设备明明接了却读不到"的原因：地址 0x36 会变成"对 0x1B 说话"。

### 5.3 `AS5600_DEG_PER_LSB`

```c
#define AS5600_RAW_MAX     4096u
#define AS5600_DEG_PER_LSB (360.0f / (float)AS5600_RAW_MAX)   /* 0.087890625 */
```

12 位 = 2¹² = **4096** 个刻度，一圈 360°：

| 原始值 | 角度 |
|---|---|
| 0 | 0° |
| 1024 | 90° |
| 2048 | 180° |
| 4095 | **359.912°**（不是 360°，最大值差一格） |

= 每格 `0.0879°`。**这就是理论分辨率**，但机械安装误差（同轴度、气隙）通常有 ±1~2°，
所以别指望它真能干到 0.09°。

### 5.4 `AS5600_I2C_TIMEOUT_MS = 2` —— 为什么必须这么短

```c
#define AS5600_I2C_TIMEOUT_MS 2u
```

底座闭环 **20ms 一个节拍**。一次 I²C 读如果阻塞 2ms，一拍还剩 18ms 干别的，够。

如果写成 100ms：I²C 一旦卡死（F103 硬件 I²C 有著名的总线死锁问题），
**整个控制循环停摆 100ms** —— 5 个控制拍全丢，底座在这 100ms 里是"闭着眼睛"的，会冲出去。

> **宁可读失败、判故障、让它停转，也不要卡住。**
> 这和"刹车坏了就熄火"是一个道理。

### 5.5 `as5600_init()`

```c
uint8_t as5600_init(void)
{
  s_present = 0u;
  {
    uint8_t status = 0xFFu;

    /* ① 能不能读到 STATUS 寄存器 */
    if (HAL_I2C_Mem_Read(&hi2c1, AS5600_ADDR, AS5600_REG_STATUS,
                         I2C_MEMADD_SIZE_8BIT, &status, 1u,
                         AS5600_I2C_TIMEOUT_MS) != HAL_OK)
    {
      return 0u;        /* 芯片没应答：没接 / 地址错 / 上拉没接 */
    }

    /* ② 有没有磁铁 —— bit5 = MD */
    if ((status & 0x20u) == 0u)
    {
      return 0u;
    }

    s_present = 1u;
  }
  return s_present;
}
```

**关键在 ②：能读寄存器 ≠ 能测角度。**

芯片应答了只说明"我在"，但前面没磁铁时，`ANGLE` 寄存器给的是**噪声**。
拿噪声去闭环比读失败更危险（读失败还能判故障，噪声看起来像合法数据）。
所以判 `MD == 0` 就当作"不在线"。

> 🔧 **可以扩展的地方**：STATUS 还有 bit3 = ML（磁场弱）、bit4 = MH（磁场强）。
> 以后读数不稳时，把这两个也判上，能直接告出"气隙不对"——现在没做，属于可选改进。

### 5.6 `as5600_read_deg()`

```c
if (HAL_I2C_Mem_Read(&hi2c1, AS5600_ADDR, AS5600_REG_ANGLE_H,
                     I2C_MEMADD_SIZE_8BIT, buf, 2u,
                     AS5600_I2C_TIMEOUT_MS) != HAL_OK)
{
  return 0u;
}

raw  = (uint16_t)(((uint16_t)buf[0] << 4) | ((uint16_t)buf[1] >> 4));
*deg = (float)raw * AS5600_DEG_PER_LSB;
return 1u;
```

#### ① 为什么**一次读 2 字节**，而不是分两次读

这是个真实的竞态：

```
假设现在 raw = 0x0FF8（4088，约 359.6°）
  先读高字节 0x0F  ✔ 此刻正确
  ↓ 转子继续转，跨过 4095 → 0
  再读低字节 0x08  ✘ 这时候已经是不一样的位置了
  拼起来 = (0x0F << 4) | 0x08 = 0xF8 = 248
```

**真实值 8，读出来 248 → 误差 240 格 ≈ 21°**。闭环看到 21° 的误差会猛甩一下。

如果顺序反过来（高字节读到 0x00、低字节读到旧的 0xF8），误差能到 350° 量级，**直接飞**。

> 一次 `HAL_I2C_Mem_Read(..., buf, 2u, ...)` 是**一个完整的 I²C 事务**
> （起始 → 写寄存器地址 → 重复起始 → 连续读 2 字节 → 停止），中间不会被别的 I²C 事务插进来。
> 这是唯一稳妥的写法。

#### ② 位拼接 `(buf[0] << 4) | (buf[1] >> 4)`

12 位数据被这么摆：

```
高字节 buf[0]：  bit7 bit6 bit5 bit4 bit3 bit2 bit1 bit0
                   ↓    ↓    ↓    ↓
                 bit11 bit10 bit9 bit8        ← 12 位的【高 4 位】

低字节 buf[1]：  bit7 bit6 bit5 bit4 | bit3 bit2 bit1 bit0
                   ↓    ↓    ↓    ↓
                 bit3 bit2 bit1 bit0          ← 12 位的【低 4 位】
                 （低 4 位是保留的，没用）
```

所以：

- `buf[0] << 4` → 把高 4 位挪到 bit11..8，低 4 位腾空
- `buf[1] >> 4` → 把低 4 位挪到 bit3..0
- 两者**按位或** → 拼成完整的 12 位

> 注意是 `>> 4` 不是 `& 0x0F` 再拼 —— 右移 4 位后高位自动补 0，效果一样但少一步。

### 5.7 `#define AS5600_HW_READY 1`

```c
#if AS5600_HW_READY
  ... 真实现 ...
#else
  (void)deg;    /* 占位实现：不改 *deg，只报告失败 */
  return 0u;
#endif
```

历史：2026-11-09 之前 I²C1 还没在 CubeMX 里打开，这里是个占位实现，保证整个工程能编过。
T4 把 MPU6050 接上同一条总线时，AS5600 一并换成真实现，所以现在是 **1**。

**用 `#if` 而不是 `if`**：`if (0)` 的代码照样会被编译进 flash（哪怕优化掉一部分），
`#if` 是编译期直接不生成 —— 占位实现一行都不会进固件。

## 6. `arm_joint.c` 里的两处

### 6.1 `base_read_deg()` —— 全工程唯一的 AS5600 读数入口

```c
static uint8_t base_read_deg(float *deg)
{
  float raw = 0.0f;

  if (as5600_read_deg(&raw) == 0u)
  {
    return 0u;                       /* 读失败：*deg 保持不动 */
  }

  *deg = wrap180(ARM_BASE_ENC_SIGN * (raw - ARM_BASE_ENC_ZERO_DEG));

  return 1u;
}
```

**为什么必须只在这里读一次**：

如果 `vel_tick()` 里自己换算一次、`arm_joint_get_deg()` 里又自己换算一次，
**只要两处漏掉一个 `SIGN`，同一时刻就会有两个互相矛盾的"机械角"** ——
闭环按 A 坐标系走、`q1_act` 报 B 坐标系，这种 bug 能查一整天。

所以约定：**`as5600_read_deg()` 除了这个函数，别的地方一律不许调。**

三处调用方（都改走 `base_read_deg()` 了）：

| 函数 | 用途 |
|---|---|
| `vel_tick()` | 闭环里的 `meas` |
| `arm_joint_get_deg()` | 上报 `q1_act` |
| `arm_joint_hold_position()` | 把手动模式交还闭环时，把目标钉在当前实际位置 |

### 6.2 `vel_tick()` —— 闭环五步

每 20ms 跑一次，只对 `kind == ARM_JOINT_VEL` 的关节生效（现在只有底座）。

#### ① 读角度

```c
if (base_read_deg(&meas) == 0u)
{
  s_base_fault = 1u;
  us_stop = (c->us_stop != 0u) ? c->us_stop : SERVO_US_MID;
  (void)arm_set_us(joint, us_stop);
  return;
}
s_base_fault = 0u;
```

**读不到就停转，不猜。** 连续舵机的"停"是 `us_stop`（一般是 1500µs）。
同时置 `s_base_fault`，它会反映到 `0x10` 帧的 bit4（I²C 失效）。

> 对比一下错误做法：读失败就 `return` 不管 —— 舵机会**保持上一次的脉宽继续转**，
> 而闭环已经瞎了。这是最典型的"越修越糟"的写法。

#### ② 算误差

```c
err = wrap180(s_tgt_deg[joint] - meas);
s_base_err = (err >= 0.0f) ? err : -err;   /* 绝对值，给状态位用 */
```

`s_base_err` 的绝对值后面有两个用途：死区判断、`arm_joint_moving()` 判"还在动没动"。

#### ③ 软件限位（走线保护）

```c
if (((meas <= (float)c->deg_min) && (err < 0.0f)) ||
    ((meas >= (float)c->deg_max) && (err > 0.0f)))
{
  us_stop = ...;
  (void)arm_set_us(joint, us_stop);
  return;
}
```

翻译成人话：

- **已经到（或越过）下限了，还想继续往下走** → 停
- **已经到（或越过）上限了，还想继续往上走** → 停

这是给 **360° 回转时底座线缆会绞** 这件事留的余量。计划填 `±170°`，剩下 ±10° 当安全垫。

> 注意它只拦"继续往外走"，**不拦"往回走"** —— 卡在限位外面时仍然允许你回来，
> 否则一旦越界就永远出不来了。

#### ④ 前馈 + 比例 + 限幅 + 死区

```c
#if ARM_BASE_FF_ENABLE
  u_ff = s_ff_dps[joint] * c->us_per_dps;
#else
  u_ff = 0.0f;
#endif

u = u_ff + (ARM_BASE_KP_US_PER_DEG * err);

if (u >  ARM_BASE_U_MAX_US) { u =  ARM_BASE_U_MAX_US; }
if (u < -ARM_BASE_U_MAX_US) { u = -ARM_BASE_U_MAX_US; }

if (s_base_err < ARM_BASE_DEADBAND_DEG) { u = 0.0f; }
```

**口诀：前馈出力，比例收尾。**

| 只有比例 | 只有前馈 |
|---|---|
| 追匀速目标时**稳定落后** 几十度（稳态误差 `e = ω/Kp`） | 模型不准 → 慢慢跑偏，没人收 |

所以将来要做两件事：`ARM_BASE_FF_ENABLE` 改成 1、`us_per_dps` 标出来。

**限幅**：`±300µs`。这是"最大能给出的速度指令"。
`ARM_BASE_U_MAX_US` 还有第二个身份 —— **标定 `SIGN` 时的保命开关**（见 §7）。

**死区**：误差小于 `1.5°` 就彻底停转。连续舵机在零速点附近会嗡嗡响、发热、抖。
死区就是"懒得理这么点误差"。

#### ⑤ 写脉宽

```c
us_stop = (c->us_stop != 0u) ? c->us_stop : SERVO_US_MID;
(void)arm_set_us(joint, (uint16_t)((float)us_stop + u));
```

`us_stop` 为 0 时退回 `SERVO_US_MID`（1500µs）—— 这是"没填标定值也不至于飞"的兜底。

## 7. 标定 `ZERO` 和 `SIGN`（四步，第 0 步不能跳）

### 先看后果：`SIGN` 填反会发生什么

```
真实情况：舵机正转 → 编码器读数减小（SIGN 应该是 −1，却填了 +1）

第 1 拍：tgt = 10°，meas = 0°   → err = +10°  → u = +30µs → 舵机正转
第 2 拍：meas 变成 350°（绕过 0） → err = wrap180(10 − 350) = +20° → u = +60µs → 转更快
第 3 拍：meas 变成 340° → err = +30° → u = +90µs → 转更快
...
```

**误差越来越大，输出越来越大 —— 这就是正反馈。**
舵机以最大速度冲向限位，`ARM_BASE_U_MAX_US` 限幅了也照样是"最大速度顶着"。
几十秒后就开始闻糊味。

更阴的是：`status` 的 bit2 故障位**不一定报**，因为在错误的坐标系里 `s_base_err` 一直在减小。
你看到的可能只是"底座转得有点快"。

### 标定流程

| 步 | 做什么 | 怎么判断对了 |
|---|---|---|
| **0** | **把 `ARM_BASE_U_MAX_US` 从 `300.0f` 临时改成 `50.0f`** | 符号填错时也只是慢爬，不会飞 |
| 1 | 手把底座转到**机械零位**（手臂朝正前方），读 `as5600_read_deg()` 的值 → 填 `ARM_BASE_ENC_ZERO_DEG` | 填完再读 `base_read_deg()` 应该约等于 `0.0` |
| 2 | 发 `q1 = +5°` | 底座朝**你说的正方向**转 → `SIGN = +1.0f`；朝反方向转 → `SIGN = -1.0f`，再发一次确认 |
| 3 | **`U_MAX_US` 调回 `300.0f`** | |
| 4 | 发给 `q1 = +30°`，看它**停不停在 30° 附近** | 停住了 → 闭环成立 |

> ✅ **判据要严格**：第 2 步不要"看着像是往右转"就完事。
> 拿手挡一下、或者看 `q1_act` 是在增大还是减小 —— **以数字为准，不以眼睛为准**。

## 8. 常见误解（都是真会踩的）

### 误解 1：「读出来 0~360°，那就是机械角」

❌ 那是**磁铁的**坐标系。不减去 `ZERO`、不乘 `SIGN`，偏置和方向全错。
→ 这就是 `base_read_deg()` 存在的理由。

### 误解 2：「分两次读高低字节没关系，反正只差几毫秒」

❌ 跨 `4095 → 0` 那条边界时，会拼出一个错误值（§5.6 ①），误差 20°~350°。
→ 必须一次读 2 字节。

### 误解 3：「磁铁随便一颗圆片都行」

❌ **轴向充磁**（N/S 在上下两面）的普通圆片磁铁装上去，**读数一动不动**。
AS5600 测的是**穿过芯片表面的磁场方向**，轴向磁铁转起来方向没变。
→ 必须**径向充磁**（N/S 在直径两侧）。

### 误解 4：「没磁铁也能读个大概」

❌ 没磁铁时 `ANGLE` 给的是噪声，看起来像合法数据。→ `init()` 里判 `MD` 位挡掉。

### 误解 5：「AS5600 可以接 5V，模块上可能有稳压」

⚠️ 就算**模块**上带 LDO 能扛 5V，**它的上拉电阻也会把 SDA/SCL 拉到 5V**。
同一条总线上的 MPU6050 会被这 5V 打死（它没有 5V 容限）。
→ 两块都接 **3.3V**，没有例外。

### 误解 6：「编码器读数就是 `q1_act`，直接报上去」

❌ 要经过 `base_read_deg()` 换算。现在 `arm_joint_get_deg()` 已经帮你做了。

### 误解 7：「换板了，编码器也要重标 `ZERO`/`SIGN`」

❌ **不用**。`ZERO` 和 `SIGN` 只跟**机械安装**有关（磁铁粘在哪、朝哪），跟主控板毫无关系。
换板只影响 PWM 引脚和波形实测。
> 反过来：**拆装机械臂、重贴磁铁之后，必须重标**。

### 误解 8：「12 位 = 0.09°，所以整体精度是 0.09°」

❌ 0.09° 只是**理论分辨率**。实际精度由同轴度、气隙、磁铁充磁均匀度决定，通常 **±1~2°**。
→ 所以死区设 1.5° 是有道理的：比传感器噪声大，比能接受的定位误差小。

## 9. 自测题（10 题，答案在最后）

**Q1.** `AS5600_ADDR` 为什么写 `(0x36u << 1)`，而不是直接 `0x36`？

**Q2.** 为什么读角度时必须**一次**读 2 字节？分两次读在什么情况下会出错？

**Q3.** `raw = (buf[0] << 4) | (buf[1] >> 4)` 里，为什么是 `>> 4` 而不是 `& 0x0F`？

**Q4.** `as5600_read_deg()` 失败时为什么不把 `*deg` 置 0？

**Q5.** `as5600_init()` 里判断 `status & 0x20` 是在查什么？为什么查不到就当"不在线"？

**Q6.** 如果 `ARM_BASE_ENC_SIGN` 填反了，画出前 3 个控制拍的 `meas → err → u` 变化，说明为什么危险。

**Q7.** `vel_tick()` 里读角度失败时，为什么必须**显式**写一次 `us_stop`，而不是直接 `return`？

**Q8.** 软件限位为什么只拦"继续往外走"，不拦"往回走"？

**Q9.** `ARM_BASE_I2C_TIMEOUT_MS` 为什么是 2ms 而不是 100ms？

**Q10.** 假设 `ZERO = 0`、`SIGN = +1`，`as5600_read_deg()` 读到 `210.5°`，`s_tgt_deg = 0`。
问：`meas`、`err`、`u`（设 `Kp = 3`、误差 210 未进死区）分别是多少？舵机会往哪转？

---

### 答案

**A1.** I²C 7 位地址是 `0x36`，但线上第 8 位要当读写位。HAL 要的是**已左移的 8 位地址**，
写操作 `0x6C`、读操作 `0x6D`。不左移 = 在对 `0x1B` 说话，芯片永远不应答。

**A2.** 因为转子在两次读之间会转。若先读高字节（此刻 `0x0F`），转子跨过 `4095→0`
之后读低字节（`0x08`），拼出来是 `248` 而真实值是 `8`，误差 ≈ 21°。反向撕裂更离谱。
一次 `HAL_I2C_Mem_Read(..., 2u, ...)` 是一个完整事务，中间不会被插进来。

**A3.** 右移 4 位后高 4 位自动补 0（`uint8_t` 提升为 `uint16_t` 后高位全是 0），
效果等同于 `& 0x0F` 赋值到低 4 位，但少一步运算。两种写法都对，`>> 4` 更短。

**A4.** 为了让调用方能区分"真的在 0°"和"读失败"。置 0 的话，闭环会以为手臂跑到了 0°
然后猛甩回去 —— 把"读不到"伪装成"合法数据"，是无声错误里最危险的一种。

**A5.** 查 `MD`（Magnet Detected，bit5）。没有磁铁时 `ANGLE` 寄存器给的是噪声，
拿噪声去闭环比读失败更危险（噪声看起来像合法值）。所以 `MD == 0` 直接判"不在线"。

**A6.** 设真实关系是"舵机正转 → 读数减小"，却填了 `+1`：

| 拍 | 舵机实际 | 读数 | `meas` | `err = tgt−meas` | `u` |
|---|---|---|---|---|---|
| 1 | 0° | 0° | 0° | +10° | +30µs → 正转 |
| 2 | 转了 20° | 340° | 340° | −330°→wrap→ +30° | +90µs → 转更快 |
| 3 | 转了 45° | 315° | 315° | +45° | +135µs → 更快 |

误差与输出同步增大 = **正反馈**。舵机以最大速度顶到限位，直到烧掉。这就是标定前必须
把 `U_MAX_US` 降到 50 的原因。

**A7.** 因为舵机会**保持上一次的脉宽继续转**。直接 `return` 等于"控制盲了但电机还在听旧指令"。
必须显式写 `us_stop` 让它停下来，同时置 `s_base_fault` 让上位机知道。

**A8.** 只拦"往外"是留**退路**。如果连往回也拦，一旦越界就永远出不来（卡死）。
限位的作用是"别走太远"，不是"把门焊死"。

**A9.** 底座闭环 20ms 一拍。读超时 2ms，一拍还剩 18ms 干别的。
如果给 100ms，I²C 卡死时整个控制循环停摆 100ms —— 丢 5 个控制拍，底座在盲区里冲出去。
**宁可读失败判故障，也不要卡住。**

**A10.**

```
meas = wrap180( +1 × (210.5 − 0) ) = wrap180(210.5) = 210.5 − 360 = −149.5°
err  = wrap180( 0 − (−149.5) ) = +149.5°
u    = 3 × 149.5 = 448.5 → 限幅到 +300µs
```

`u > 0` → 脉宽 = `1500 + 300 = 1800µs` → **舵机以最大速度正转**（朝"目标 0°"的方向）。

> 注意 `wrap180(210.5)` 出来的 `−149.5°` 不是笔误：`210.5°` 和 `−149.5°` 在圆周上是**同一个点**，
> 但作为"机械角"取 `−149.5` 才能和 `tgt = 0` 算出 `+149.5` 这么个小角度误差。
> 如果用 `210.5` 直接减，会得到 `−210.5` 这种"绕远路"的误差 —— **这就是 §1 里 `wrap180` 的意义**。
