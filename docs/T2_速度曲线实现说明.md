# T2 速度曲线实现说明（梯形 / S 曲线 / 200Hz 插补）

> 对应提交：见 `plan.md` §8（2026-11-11 13:xx）。
> 涉及文件：`Core/Inc/arm_cfg.h`、`Core/Inc/proto.h`、`Core/Src/proto_app.c`。
> **`main.c` 一行没动** —— 节拍拆分全在 `proto_app_poll()` 内部做完了。

---

## 0. 一句话

以前 `0x20` 的 `profile` 字段被整个忽略，三档全按"线性匀速"跑；
现在严格按任务书实现 **0 阶跃 / 1 梯形 / 2 S 曲线**，
并把插补节拍从 50Hz 提到 **200Hz**（5ms），与 20ms 的状态帧彻底拆开。

---

## 1. 为什么非改不可

任务书 T2 原文：

> 接收目标角后，底座、肩、肘同时出发、同时到位；**插补周期不低于 200Hz**，
> 采用**梯形或 S 曲线**速度规划；**相邻两拍的角度增量连续，不允许出现阶跃**。

两个硬指标原来都不达标：

| 指标 | 原来 | 要求 | 现在 |
|---|---|---|---|
| 插补周期 | 20ms = **50Hz** | ≥ 200Hz | **5ms = 200Hz** ✅ |
| 速度规划 | 线性匀速（矩形速度曲线） | 梯形 **或** S 曲线 | 梯形 + S 曲线都做了 ✅ |
| `profile` 字段 | **完全被忽略** | 0/1/2 三档 | 三档都实现 ✅ |

**"矩形是梯形的特例"这句话在这里不能当挡箭牌**：矩形的加速段长度为 0，
意味着起步和停止那一拍的角度增量从 0 **突变**到 v —— 而任务书后半句
"不允许出现阶跃"判的正是这个突变。梯形把加速段拉开，增量才是连续的。

## 2. 三档 profile 的行为

| 载荷最后 1 字节 | 宏 | 行为 | 什么时候用 |
|---|---|---|---|
| `00` | `PROTO_PROFILE_STEP` | **阶跃**：不看 `duration`，一步写到位 | 演示"不做规划"的对比 |
| `01` | `PROTO_PROFILE_TRAP` | **梯形**：加速 → 匀速 → 减速 | 默认推荐，回零也用它 |
| `02` | `PROTO_PROFILE_SCURVE` | **S 曲线**：加速度也连续 | 要最柔和时用，峰值速度最高 |
| `> 02` | — | 降级成梯形（不报错） | 容错 |

⚠️ **协议里没有"线性匀速"这一档。** 以前代码把 `0` 当线性跑是不对的。
如果你想要"接近匀速"，把 `ARM_TRAP_ACC_RATIO` 调小即可，但那就不是梯形了。

## 3. 算法：只有两个函数

`proto_app.c` 里：

```c
static float profile_s (uint8_t profile, float tau);   // 时间进度 → 路程进度
static float profile_ds(uint8_t profile, float tau);   // 路程进度对时间的导数
```

`interp_tick()` 里的全部算法就两行：

```c
tau = (float)t / (float)s_dur_ms;      // 时间走到百分之几
s   = profile_s(s_profile, tau);       // 路程该走到百分之几
q   = s_q_from[j] + (dq * s);          // 每轴各自的位移 × 同一个 s
```

**四个关节用同一个 `s`，所以必然同时出发、同时到达。**
`s` 是"全程进度"，不是"角度进度"——这一点想通了 T2 就没有难点了。

### 3.1 为什么用归一化时间 `tau = t/dur`

这样 `s(tau)` 只跟**比例**有关，和这段走多久完全解耦。
同一个函数，走 200ms 和走 2000ms 只是 `t`、`dur` 变了，形状一模一样。
**这正是"`duration` 只改快慢、不改终点"的数学原因。**

### 3.2 三个硬约束

```
s(0) = 0     起点必须是 0
s(1) = 1     终点必须是 1，否则四轴对不齐，而且 s_moving 清不掉
s 单调不减   否则中途会往回走
```

已用 200 点扫描验证：两条曲线逆序点都是 **0**。

## 4. 梯形：推导与那个反直觉的结论

把归一化时间切成三段（`r = ARM_TRAP_ACC_RATIO = 0.2`）：

```
时间：|←加速 20%→|←———— 匀速 60% ————→|←减速 20%→|
速度：            ╱‾‾‾‾‾‾‾‾‾‾‾‾‾‾╲
                ╱                ╲
```

设匀速段速度为 `Vp`。三块面积：

```
加速段 = Vp·r/2      匀速段 = Vp·(1−2r)      减速段 = Vp·r/2
```

总面积必须为 1（走完全程）：

```
Vp·r + Vp·(1−2r) = Vp·(1−r) = 1
                ⟹  ★ Vp = 1/(1−r)  > 1
```

**★★ 这就是梯形最反直觉的一点**：为了"补回"加减速段少走的距离，
匀速段的**峰值速度必须比平均速度高**。`r=0.2` 时高 25%。

所以"梯形比线性慢"是错的 —— **同样时长下，梯形中间那段更快。**

分段公式：

| 区间 | `s(tau)` | `ds/dtau` |
|---|---|---|
| `0 ≤ τ < r` | `τ² / (2r(1−r))` | `τ / (r(1−r))` |
| `r ≤ τ ≤ 1−r` | `(τ − r/2) / (1−r)` | `1/(1−r)` |
| `1−r < τ ≤ 1` | `1 − u²/(2r(1−r))`，`u=1−τ` | `u / (r(1−r))` |

减速段直接用 `1 − s(1−τ)` 算 —— **手推三段最容易在系数上翻车，对称性白送**。

### 验算表（r=0.2）

| τ | 0.1 | 0.2 | 0.3 | 0.5 | 0.7 | 0.8 | 0.9 |
|---|---|---|---|---|---|---|---|
| s | 0.03125 | 0.125 | 0.25 | 0.5 | 0.75 | 0.875 | 0.96875 |

对比线性（`s = τ`）：`τ=0.2` 时线性已走 **20%**，梯形只走 **12.5%**；
到 `τ=0.5` 两者都是 50%（对称点必然重合）。
**梯形起步慢、中段快、收尾慢 —— 这就是"柔和"的代价。**

## 5. S 曲线：为什么是五次多项式

```
s(τ) = 6τ⁵ − 15τ⁴ + 10τ³
```

它是满足下面四个边界条件的**最低次多项式**：

```
s(0)=0      s(1)=1
s'(0)=0     s'(1)=0        起点终点速度为 0
s''(0)=0    s''(1)=0       起点终点加速度也为 0   ← 这一条才是"S"
```

二阶导 `120τ³ − 180τ² + 60τ` 在 `τ=0` 和 `τ=1` 处都恰为 0，
所以起停既不"顿"（速度连续）也不"抽"（加速度连续）。

峰值速度：`s' = 30τ²(1−τ)²`，`τ=0.5` 时 `30×0.25×0.25 = 1.875`。

| 曲线 | 峰值速度 / 平均速度 |
|---|---|
| 线性 | 1.00 |
| 梯形 r=0.2 | **1.25** |
| S 曲线 | **1.875** |

**峰值越高 → 同样时长里中间那段越快 → 对舵机瞬时力矩要求越高。**
轻负载用 S 曲线没问题，带载时要注意。

## 6. 200Hz：拆了但不多出一帧

`proto_app_poll()` 里现在是两个独立节拍：

```c
if ((now - s_ms_interp) >= ARM_INTERP_TICK_MS)   // 5ms
{
    interp_tick(now);        // 只算角度，不出帧
    arm_joint_tick(now);     // 底座闭环（位置型关节什么都不做）
}

if ((now - s_ms_report) >= APP_REPORT_MS)        // 20ms
{
    send_status(now);        // 只出帧，不推进插补
}
```

编译期有两条保护：

```c
#if (APP_REPORT_MS < ARM_INTERP_TICK_MS)
#  error "状态帧周期不能短于插补周期"
#endif
#if ((APP_REPORT_MS % ARM_INTERP_TICK_MS) != 0)
#  error "状态帧周期必须是插补周期的整数倍，否则 0x10 的节拍会抖"
#endif
```

### 一个必须说清楚的点

**200Hz 不会让舵机动得更细。** 舵机 PPM 是 50Hz，`CCR` 实际上每 20ms
才真正生效一次 —— 这是模拟舵机的物理限制，200Hz 改不了。

那 200Hz 的价值在哪？在**任务书判的那句话**："相邻两拍的角度增量连续"。
5ms 一拍算出来的增量是连续变化的；20ms 一拍算出来的是大台阶。

**别在答辩时说"我把舵机刷新率提到 200Hz 了"，那是错的。**

## 7. 怎么验收（三条曲线，看角速度图）

用 ArmHost 的帧生成器，类型 `0x20`，只要改**载荷最后 1 字节**（profile）。

以 J4 从 30° 走到 60°、时长 2000ms 为例（J1~J3 固定 90°）：

| 想看什么 | 载荷 | 角速度曲线应该长这样 |
|---|---|---|
| **阶跃** | `84 03 84 03 84 03 58 02 D0 07 00` | 一根竖线（瞬间到位） |
| **梯形** | `84 03 84 03 84 03 58 02 D0 07 01` | 斜坡↑ → 平顶 → 斜坡↓ |
| **S 曲线** | `84 03 84 03 84 03 58 02 D0 07 02` | 中间平顺的钟形，没有折角 |

### 峰值速度对表（30° / 2000ms，平均 15 °/s）

| 曲线 | 峰值 | 出现在 |
|---|---|---|
| 线性（旧行为，已不存在） | 15 °/s | 全程 |
| **梯形** | **18.75 °/s** | 0.4s ~ 1.6s 的整个匀速段 |
| **S 曲线** | **28.1 °/s** | 约 1.0s（中点） |

**这是本轮最容易验证的一件事**：梯形应该在 18~19 °/s 平一段，
S 曲线应该是个尖一点、圆一点的钟形，峰值接近 28 °/s。

### ⚠️ 之前的测试帧现在会瞬跳

你之前测 T2 用的帧最后一位都是 `00`（profile = 阶跃）。
**改完之后同样的帧会直接跳过去**，不是 bug，是终于按协议执行了。
要继续测插补，把最后一位改成 `01` 或 `02`。

## 8. 回零为什么固定用梯形

`0x21` 回零和上电自动回零都调用：

```c
move_start(ARM_HOMING_MS, PROTO_PROFILE_TRAP);
```

理由：

1. **每次上电都要跑一遍**，必须稳，不能有冲击
2. 梯形峰值 1.25 倍，S 曲线 1.875 倍 —— 回零是"贴着限位走"的动作，
   峰值速度越低越不容易撞机械限位
3. 不用阶跃：`ARM_HOMING_MS` 就是为"柔和回零"存在的，阶跃会让它形同虚设

## 10. 还没做的

- **`duration = 0` 配合梯形 / S 曲线**：协议写"为 0 表示按最大速度"，
  现在实现成"按阶跃处理"（不插补）。严格说应该按一个最大速度去算时长，
  但舵机没有速度反馈，标定"最大速度"意义不大。**如果评审问，就这么答。**
- **加速度限制**：现在梯形的"加速度"是由时长和行程反算的，不是独立参数。
  真正的做法是给一个 `acc_max`，时长不够时自动延长 `duration`。
  任务书没要求，不做。
