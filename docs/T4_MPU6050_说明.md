## 1. 这一版做了什么

| 要求（任务书 T4） | 实现 |
|---|---|
| 硬件 I²C，400kHz | I²C1（PB6=SCL / PB7=SDA），`MX_I2C1_Init()` 在 T0 就已生成，`ClockSpeed = 400000` |
| 读 WHO_AM_I 确认器件 | 上电读 `0x75`，必须等于 `0x68`；不对就不当在线 |
| 读加速度 + 角速度 | 从 `0x3B` 连续读 14 字节（ax/ay/az/temp/gx/gy/gz） |
| 静止 5~10s 求陀螺零偏 | `0x33` 启动，非阻塞采 5s（250 个样本）取平均；中途检测到运动就作废 |
| 末端倾角显示 | 加速度算绝对 pitch，填进 `0x10` 的 offset 16（单位 0.1°） |
| 目标角 + 实测倾角同屏 | 上位机已有 `q2_tgt`；`pitch` 就是实测倾角。差一个安装零偏，见 §6 |
| 失效 1s 内进安全态 | 连续 3 次读失败（60ms）停读，`LOST_MS=200ms` 判故障 → 停插补 + 冻结脉宽 + bit2/bit4 |
| 拔 SDA 停机、插回恢复 | 每 500ms 重探测；恢复后自动清故障位，但**不会自己动**，要等新的 `0x20` |

**没有做的**（避免过度设计，验收不要求）：

- 互补滤波 / 卡尔曼滤波 —— pitch 只取加速度，静止不漂；动态响应以后需要再加
- 陀螺积分角度 —— 会漂，且没有磁力计做绝对参考
- 零偏写 Flash —— 每次上电重标 5 秒，避免擦写寿命和"标定值过期"问题

## 2. 接线

| MPU6050（GY-521 等模块） | STM32F103C8T6 | 说明 |
|---|---|---|
| VCC | 3.3V | 模块带 LDO 时 5V 也能进，但逻辑电平仍是 3.3V |
| GND | GND | 必须共地 |
| SCL | PB6 | I2C1_SCL，和 AS5600 共用 |
| SDA | PB7 | I2C1_SDA，和 AS5600 共用 |
| AD0 | GND | 地址 `0x68`；接 3.3V 是 `0x69`，代码里 `MPU6050_ADDR_7BIT` 要改 |
| INT | 不接 | 本工程轮询，不用中断 |

**上拉电阻**：SDA/SCL 各 4.7kΩ 到 3.3V。

- GY-521 模块板上通常自带 4.7k；AS5600 模块也常自带。
- 两套并联后约 2.2k，400kHz 下一般没问题；如果通信不稳（`WHO_AM_I` 时好时坏），
  先拆掉其中一套，只留一套 4.7k。
- **不要**用 STM32 内部上拉（约 40k），400kHz 下上升沿太慢。

**和 AS5600 共总线**：地址不同（`0x68` / `0x36`），所有 I²C 调用都在主循环里顺序执行，
不存在并发。两个器件的 4.7k 上拉是并联关系，不是"各拉各的"。

### 2.1 装在哪一节（机械臂上）

**装 J3 小臂，靠近 J4 夹爪那一端的上表面**；不要装底座，也不要装夹爪的动片。

| 位置 | 能不能 | 原因 |
|---|---|---|
| J1 底座 | ❌ | 只绕竖直轴转，pitch 始终约 0，测不到俯仰 |
| J2 大臂 | ⚠️ 只适合临时验证 | pitch 只反映 q2；验收要求"小臂/末端"，最终要挪到小臂 |
| **J3 小臂** | ✅ **最终安装位置** | 任务书要求"小臂/末端"；pitch ≈ q2 + q3 + 常数（见 §6.2） |
| J4 夹爪动片 | ❌ | 夹爪开合会动、会震，数据不可信 |

方向：**X 轴沿小臂指向夹爪，Z 轴朝上**（芯片丝印朝上），用 §4.3 的两步确认。
如果结构上只能贴在侧面，先按 §4.3 判断，再改 `MPU6050_PITCH_AXIS` / `MPU6050_PITCH_SIGN`，不要硬掰安装方向。

## 3. 代码结构

```
proto_app.c   20ms 节拍：mpu6050_tick() → 故障判定 → 插补/执行/上报
     │        0x30/0x33 的收帧处理也在这里
     ↓
mpu6050.c     I²C 读写、14 字节解析、倾角计算、零偏标定、掉线重连
     ↓
HAL_I2C       hi2c1（main.c 里 CubeMX 生成）
```

- `mpu6050.c` 不碰 PWM、不碰协议帧，只输出物理量 —— 和 `as5600.c` 同一层。
- `arm_pwm.c` 仍然完全不知道 I²C 的存在。
- `main.c` 只在 `t0_setup()` 里调一次 `mpu6050_init()`，并在横幅里打一行在线状态。

**上电日志**（USART1，PA9/PA10，115200）：

```
[T4] MPU6050 在线 (WHO_AM_I=0x68, ±2g/±500dps, I2C1 400kHz)
```

或：

```
[T4] MPU6050 未检测到（pitch 填 0，其余功能照常；见 docs/T4_MPU6050_说明.md）
```

> 没接模块时**不会**报故障，也不影响舵机 —— `MPU6050_REQUIRED` 默认是 0。
> 等模块固定到机械臂上、确认不会松动后，再改成 1。

## 4. 0x30：传感器原始数据

### 4.1 查询

上位机发 1 字节（内容随意，习惯填 `0x01`）：

```
A5 30 01 01 42
```

| 字节 | 值 | 说明 |
|---|---|---|
| 0 | `A5` | SOF |
| 1 | `30` | 类型 |
| 2 | `01` | 载荷长度 |
| 3 | `01` | 查询 |
| 4 | `42` | CRC8（前 4 字节） |

### 4.2 应答

固定 17 字节载荷：

| offset | 类型 | 字段 | 单位 / 换算 |
|---|---|---|---|
| 0 | int16 | `ax` | 原始计数，±2g 量程，16384 LSB/g |
| 2 | int16 | `ay` | 同上 |
| 4 | int16 | `az` | 同上；水平放置约 `+16384` |
| 6 | int16 | `gx` | 原始计数，±500°/s，65.5 LSB/(°/s) |
| 8 | int16 | `gy` | 同上 |
| 10 | int16 | `gz` | 同上 |
| 12 | int16 | `temp` | 温度原始值；℃ = `temp / 340 + 36.53` |
| 14 | int16 | `pitch` | **已算好的倾角**，0.1°，抬头为正 |
| 16 | u8 | `status` | 见下表 |

**status 位**（这是 0x30 自己的状态字节，和 0x10 / 0x32 的都不是一回事）：

| bit | 宏 | 含义 |
|---|---|---|
| 0 | `PROTO_SENSOR_ST_OK` | 最近一次读数有效（能信） |
| 1 | `PROTO_SENSOR_ST_CALIB` | 正在零偏标定 |
| 2 | `PROTO_SENSOR_ST_FAULT` | 传感器故障（丢线 / 要求必须装但没装） |
| 3 | `PROTO_SENSOR_ST_CALIBRATED` | 本上电周期内零偏已标定 |

**示例**（抬头 12.3°、已标定）：

```
A5 30 11 F2 5E 00 00 3E 88 00 00 00 00 00 00 00 00 00 7B 09 D5
   └─ 载荷 ──────────────────────────────────────────────┘
   ax=-3490  ay=0  az=16008  gx=0  gy=0  gz=0  temp=0  pitch=123  st=0x09
```

`st=0x09` = bit0（有效）+ bit3（已标定）。`ax/az` 和 `pitch` 是自洽的：
`atan2(3490, 16008) ≈ 12.3°`，倾斜时 `az` 会从 16384 略降，不是恒定值。

### 4.3 怎么用它判断安装方向

1. 模块**水平**放置，读 `0x30`：`pitch` 应接近 0，`az` 应接近 `+16384`。
2. 把模块**抬头 30°**：`pitch` 应变成 `+300` 左右。
   - 变成 `-300` → `MPU6050_PITCH_SIGN` 改成 `-1.0f`。
   - 数值基本不变、`ay` 在变 → 模块绕 Z 转了 90°，把 `MPU6050_PITCH_AXIS` 改成 `MPU6050_PITCH_AXIS_Y`。
3. 静止时 `pitch` 抖动应在 ±0.5° 内（低通后）。抖得厉害先查电源和上拉，不是算法问题。

## 5. 0x33：陀螺零偏标定

### 5.1 为什么需要

MPU6050 的陀螺零偏（静止时输出不为 0）随芯片、温度变化，典型 ±2°/s，大的能到 ±10°/s。
不标定的话，`0x30` 里的 `gx/gy/gz` 永远带一个固定偏置；虽然 **pitch 不受影响**（pitch 只用加速度），
但报告里"角速度"这一项会显得不准，而且以后要做积分/滤波时零偏必须扣掉。

### 5.2 命令（1 字节）

| 值 | 宏 | 动作 |
|---|---|---|
| `0x00` | `PROTO_CALIB_QUERY` | 查询状态，不改变任何东西 |
| `0x01` | `PROTO_CALIB_START` | 开始标定（要求静止 5s） |
| `0x02` | `PROTO_CALIB_ABORT` | 中止（已完成的零偏保留） |

示例：

```
A5 33 01 00 F8     查询
A5 33 01 01 FF     开始
A5 33 01 02 F6     中止
```

### 5.3 应答（9 字节）

| offset | 类型 | 字段 |
|---|---|---|
| 0 | u8 | `state`：0=IDLE，1=RUNNING，2=DONE，3=ERROR |
| 1 | u8 | `progress`：0~100 |
| 2 | u8 | `reason`：0=OK，1=传感器不在线，2=I²C 失败，3=检测到运动 |
| 3 | int16 | `bias_x`，0.1°/s |
| 5 | int16 | `bias_y`，0.1°/s |
| 7 | int16 | `bias_z`，0.1°/s |

**完成示例**（bias = +1.2 / −0.8 / +0.3 °/s）：

```
A5 33 09 02 64 00 00 0C FF F8 00 03 94
         │  │  │  └x─┘ └y─┘ └z─┘
         │  │  └ reason=0
         │  └ progress=100
         └ state=2 (DONE)
```

**被拒绝示例**（机械臂还在动就点了开始）：

```
A5 33 09 03 00 03 00 00 00 00 00 00 06
         state=3(ERROR) progress=0 reason=3(MOVING)
```

### 5.4 标定流程

1. 机械臂上电，**所有关节静止**（手别碰，底座别转）。
2. 发 `0x33 01`。
3. 每 200~500ms 发 `0x33 00` 查进度；`progress` 从 0 涨到 100，约 5 秒。
4. `state=2` 表示完成，把 `bias_*` 记进报告。
5. 标定过程中如果晃了机械臂 → `state=3, reason=3`，重新来一次。

**注意**：

- 结果只在 RAM，**断电就没了**，每次上电后重新标。
- 标定期间 `0x30` 仍可读，`pitch` 正常。
- 标定不会让机械臂动，但会拒绝新的 `0x20` 吗？**不会** —— 它只拒绝"开始标定"这个动作；
  如果标定途中收到 `0x20` 并开始运动，`calib_accumulate()` 检测到角速度超 30°/s 会立刻作废本次标定。
- 建议在**上电回零之后、正式开始跑动作之前**标定。

## 6. 倾角定义与"目标角 vs 实测角"

### 6.1 定义

默认安装（芯片丝印朝上，X 轴指小臂前方，Z 轴朝上）：

```
pitch = atan2(−ax, sqrt(ay² + az²))
```

- **抬头为正**，水平为 0，范围约 ±90°。
- 分子取 `−ax`：静止时加速度计测到的是"支撑力"方向（+1g 朝上），不是重力方向。
  水平时 `ax=0, az=+1g` → pitch=0；抬头 θ 时 `ax=−g·sinθ, az=g·cosθ` → pitch=+θ。
- 只用了加速度，所以**静止不漂**；快速晃动时会有几度的动态误差（验收只要求静止 ≤3°）。

> **芯片的 XYZ 跟着小臂一起转，为什么还能测绝对角？**
> 因为加速度计测的是**重力在芯片自己坐标系里的分量**，不是"芯片相对地面的角度"。
> 小臂抬 30°，重力在芯片 X/Z 上的投影就按 30° 重新分配：水平时 `ax≈0, az≈+1g`；
> 抬 30° 时 `ax≈−0.5g, az≈+0.866g`，`atan2` 反推出来还是 30°。
> 所以需要固定的是**芯片相对小臂**（别松动、别换位置），不是"芯片相对地面"。
> 只要芯片的一个轴（默认 X）沿小臂方向，小臂绕自身长轴滚转也不影响这个公式 ——
> 滚转只改变 `ay/az` 的分配，`sqrt(ay²+az²)` 不变。

### 6.2 和关节目标角的关系

`0x10` 的 `pitch` 是**传感器所在那一节的绝对倾角**，不是关节编码器角度。
按任务书把模块贴在小臂（末端）上时，小臂的绝对俯仰角约等于两个俯仰关节之和再加一个机械常数：

```
pitch_measured ≈ q2 + q3 + C
```

`C` 里包含连杆零位、贴装角度、小臂相对大臂的固定夹角。**不要试图让 C=0**，
它是机械安装决定的；报告里写清楚 C 是多少、怎么扣掉的即可。

验收时最省事的做法是**只动一个关节**：

1. 模块贴在小臂上（X 轴沿小臂指向末端，Z 轴朝上；见 §4.3 确认方向）。
2. 把 J3 固定在一个角度（比如 90°）**全程不动**，这样 `C' = q3_fixed + C` 就是常数。
3. 依次给 J2 目标 60° / 90° / 120°，每次等运动停稳（`status` bit3=0）。
4. 用第一个姿态算出 `C' = pitch − q2_tgt`，再检查另外两个姿态：
   `|pitch − (q2_tgt + C')| ≤ 3°`。
5. 把 `C'` 写进报告，注明"已扣除安装零偏"。想让它自动补掉，也可以把 `C'`
   填进 `MPU6050_PITCH_OFFSET_DEG`（注意符号），但验收不要求。

> 如果 J3 也要动，就把 `q2 + q3` 当成一个整体，和 `pitch` 比；
> 只和 `q2_tgt` 比会得到"J3 一动就差很多"的假故障。
>
> 如果为了省事把模块临时贴在大臂上，`pitch` 只跟 q2 走，关系更直接；
> 但**最终验收要按任务书贴在小臂/末端**，报告里的数据也用最终安装位置。

## 7. 故障与安全态

### 7.1 判定时间线

| 时刻 | 发生什么 |
|---|---|
| 单次读失败 | 只记数，不停机（偶发 NAK 很正常） |
| 连续 3 次失败（约 60ms） | 停止读，转入重探测（每 500ms 一次） |
| 距上次成功 > 200ms | `mpu6050_faulted()` = 1 → 停插补、冻结四路 CCR、置 bit2 + bit4 |
| 传感器恢复 | 探测成功 → 清 bit2/bit4；**但运动不会自动恢复**，要等新的 `0x20` |

任务书要求"1 秒内停止"，实际 200ms，留了 5 倍余量。

### 7.2 "停止输出"为什么是冻结而不是关 PWM

和急停的处理保持一致：**保持 CCR 不变**，舵机继续收到 50Hz 脉冲、保持当前角度。

- 如果关掉 PWM，SG90 立刻失去保持力矩，手臂会因为重力**直接掉下来** —— 比"停在原位"危险得多。
- 如果改成"回中位"，那是主动运动，更不符合"停止"的语义。
- 底座（VEL 关节）调用 `arm_joint_hold_position()`，把闭环目标改成当前角度，原地停住。

### 7.3 恢复语义

- **自动清除故障位**：插回 SDA / 接触恢复后，只要读到有效数据，bit2/bit4 自动清。
- **不自动恢复运动**：`s_moving` 在故障时已经清 0，插回后不会继续跑旧目标。
  必须由上位机重新发一帧 `0x20`。这是故意的 —— 防止拔插一下手臂突然朝几分钟前的旧目标冲。
- **急停仍然要人工清**：`0x21=3`。传感器故障和急停是两套逻辑，不要混。

### 7.4 `MPU6050_REQUIRED` 开关

```c
/* mpu6050.h */
#define MPU6050_REQUIRED 0   /* 0 = 没装也能跑；1 = 必须有 */
```

现在默认 **0**：模块还没到，T1/T2/T3 的舵机测试不能被它挡住。
等模块固定好、确认不会松动，再改成 **1** —— 那时"上电没检测到"会直接判故障，拒绝运动。
（改完要重新编译烧录。）

## 8. 测试步骤（拿到模块后照做）

### 8.1 不接模块（现在就能做）

1. 烧录，上电。
2. USART1 日志出现 `[T4] MPU6050 未检测到`。
3. 发 `0x30 00`，回 17 字节全 0、`status=0`。
4. 发 `0x10` 查询，`pitch=0`，其余字段正常。
5. 发 `0x20` 让关节动 —— **必须照常动**（这是"没装也不影响"的验证）。

### 8.2 接模块

1. **断电**接线（VCC/GND/SCL/SDA/AD0），检查 3.3V 和地没有短路。
2. 上电，日志应出现 `[T4] MPU6050 在线`。
3. 发 `0x30 00`：
   - `az ≈ +16000`（±2000 都算正常，取决于放置）；
   - 水平时 `pitch ≈ 0`；
   - `status` bit0=1。
4. 倾斜 30°，确认 `pitch` 符号和大小（见 §4.3）。

### 8.3 零偏标定

1. 机械臂静止，发 `0x33 01`。
2. 每 0.5s 发 `0x33 00`，看 `progress` 到 100、`state=2`。
3. 记下 `bias_*`，正常应在 ±5°/s 内；超过 ±20°/s 说明模块有问题或没静止。
4. 标定完后 `0x30` 的 `gx/gy/gz` 静止时应接近 0（±0.5°/s）。

### 8.4 拔线安全测试（验收重点）

1. 让 J2 走一段 `duration=3000` 的运动。
2. 运动中**拔掉 SDA**（只拔 SDA，VCC/GND 保持）。
3. 用秒表/日志看：**≤1s** 内
   - `0x10` 的 `status` bit2=1、bit4=1；
   - `pitch` 变 0；
   - 关节停止（`bit3=0`），舵机保持原位不掉。
4. 插回 SDA：
   - 500ms 内 `status` bit2/bit4 自动清 0；
   - `pitch` 恢复；
   - **手臂不会自己动**；发一帧新的 `0x20` 才继续。

### 8.5 验收对照

| 验收项 | 怎么证明 |
|---|---|
| 硬件 I²C 400kHz | 日志 `I2C1 400kHz`；`WHO_AM_I=0x68`；0x30 有非零数据 |
| 静止 5~10s 零偏 | `0x33` 5s，`state=2`，bias 在 ±5°/s 内 |
| 目标角 + 实测倾角 | J3 固定，J2 给 60/90/120，先求 `C'=pitch−q2_tgt`，再看 `|pitch−(q2_tgt+C')|≤3°` |
| 失效 1s 内安全 | 拔 SDA，≤1s bit2/bit4=1、运动停、pitch=0 |
| 重新接入可恢复 | 插回，bit 自动清，新 0x20 后正常动 |

## 9. 常见问题

**Q1：`WHO_AM_I` 读出来不是 0x68？**
- 读到 `0xFF`：SDA 被拉高没人应答 → 模块没供电 / 地址不对 / SDA 没接。
- 读到 `0x00`：SDA 被拉低 → 短路或模块坏。
- 读到 `0x70` / `0x71`：可能是 MPU6500 / MPU9250（WHO_AM_I 和 6050 不同），代码按 6050 写的，需要改地址判断和量程换算。
- AD0 接 3.3V 时地址是 `0x69`，改 `MPU6050_ADDR_7BIT`。

**Q2：能读到 WHO_AM_I，但数据全是 0？**
- 芯片还在 sleep：检查 `configure()` 是否写成功（`PWR_MGMT_1=0x01`）。
- 刚唤醒前 50ms 不读（`s_ms_ready`），等下一拍。
- I²C 只写成功、读失败：查上拉和线长。

**Q3：pitch 一直是 0？**
- `mpu6050_healthy()` 为 0 → 没数据；看 `0x30` 的 `status` bit0。
- 模块没装但 `MPU6050_REQUIRED=0` → 本来就应该填 0。
- 公式里 `az` 为 0（数据全 0）→ 回到 Q2。

**Q4：pitch 符号反了 / 倾角不随俯仰变？**
- 见 §4.3，改 `MPU6050_PITCH_SIGN` 或 `MPU6050_PITCH_AXIS`。不要改公式。

**Q5：拔了 SDA 再插回，恢复不了？**
- `init_fast()` 每 500ms 重试；如果总线被从机拉死，会在连续 2 次探测失败后 `HAL_I2C_DeInit/Init`。
- 等 1~2 秒再发 `0x30`；仍不行就断电重启（SDA 短路到地时软件救不回来）。

**Q6：Debug 编译 FLASH 94%，会不会超？**
- 当前 61624/65536，剩 3.9KB；Release 只有 36856（56%）。
- 再加功能建议烧 Release；Debug 主要用于单步调试。
- 体积大头是 USB 协议栈 + HAL I²C 传输（光 `HAL_I2C_Mem_Read` 就 1.2KB）。

## 11. 已知限制（写报告时如实写）

1. **pitch 只用加速度**：静止准、不漂；快速运动时有动态误差，没做互补滤波。
2. **零偏不保存**：每次上电要重新标 5 秒；不写 Flash 是为了寿命和避免"旧标定值"。
3. **没有磁力计**：只能测俯仰/横滚，不能测航向（yaw）；底座回转角仍靠 AS5600。
4. **安装零偏**：`pitch` 和关节角之间有一个机械常数，报告里要说明怎么扣除。
5. **Debug 体积 94%**：日常调试够用，最终演示建议 Release。
