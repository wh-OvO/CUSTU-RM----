## 1. 图 A：实物数据流

### A-1 主链路（命令 → 动作）

```text
┌─────────────────────────────────────────────────────────────┐
│ 电脑 · ArmHost.exe                                          │
│   拖 3D 关节 / 点"发送目标"                                  │
│   组帧：A5 20 0B 84 03 C2 01 ... CRC                        │
└──────────────────────────┬──────────────────────────────────┘
                           │ ① 介质：Micro-USB 线（4 芯）
                           │    协议：USB 2.0 全速 12 Mbps
                           │    延迟：≤ 1 ms（USB 1ms 帧轮询）
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ Blue Pill 板载 USB 母座                                      │
│   PA11 = DM    PA12 = DP                                    │
└──────────────────────────┬──────────────────────────────────┘
                           │ ② 片内 USB 外设 → 中断
                           │    CDC_Receive_FS() ← 中断上下文
                           │    只做一件事：塞环形缓冲
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ STM32F103C8T6 片内（72 MHz）                                │
│   link_poll → 解帧 → CRC 检查 → dispatch → on_target        │
│   插补：90.0° ──→ 1500 µs ──→ CCR = 3000                    │
│   延迟：< 100 µs                                             │
└──────────────────────────┬──────────────────────────────────┘
                           │ ③ 介质：1 根信号线 + 1 根 GND
                           │    引脚 PA0 输出 3.3V 方波
                           │    50 Hz，高电平 1500 µs
                           │    3.3V 逻辑，SG90 认（TTL 兼容）
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ SG90 舵机内部（黑盒，不归你管）                               │
│                                                             │
│   输入脉宽 ──┐                                              │
│              ├─→ 比较器 ─→ H 桥驱动 ─→ 直流电机 ─→ 齿轮减速  │
│   电位器 ────┘                              │              │
│      ↑                                      ↓              │
│      └──────── 输出轴转角 ──────────────────┘              │
│                                                             │
│   ★ SG90 自己闭环：脉宽=目标，电位器=当前，差值驱动电机      │
└──────────────────────────┬──────────────────────────────────┘
                           │ ④ 机械
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 关节转角                                                     │
│   SG90 速度约 0.1 s / 60°                                   │
│   所以一个 90° 动作需要 ≈ 150 ms                            │
└─────────────────────────────────────────────────────────────┘
```

**这条链路最关键的一句：MCU 发的是"目标脉宽"，不是"闭环控制量"。**
SG90 内部有比较器 + 电位器自己闭环，协议层只负责把角度翻译成脉宽。

### A-2 延迟账（为什么不要指望优化代码改善手感）

| 段 | 什么在花时间 | 量级 |
|---|---|---|
| ① PC → USB 座 | USB 1ms 帧轮询 | **≤ 1 ms** |
| ② 中断 → 环形缓冲 | 几十条指令 | ~10 µs |
| ③ 解帧 + 插补 + 写 CCR | 几百条指令 | ~50 µs |
| ④ CCR 生效 | 等下一个 PWM 周期（20 ms） | **≤ 20 ms** |
| ⑤ 舵机真的转到位 | 机械，0.1 s/60° | **100~200 ms** |

**结论：代码层总共只占 1.05 ms，剩下 99% 是机械。**

推论：

- 手感由舵机决定，代码改不出"更快"
- 但代码能让它**更慢**：主循环里出现一次 `HAL_Delay(100)`，④ 那 20 ms 就变 200 ms
- `interp_tick()` 的意义不是加快，是**把一次跳变摊成多拍小步**，让 ⑤ 这段机械走得平稳（不甩、不过冲）

### A-3 反馈链路（两个传感器为什么不一样）

```text
      MPU6050 (0x68)              AS5600 (0x36)
      [末端姿态]                   [底座绝对角]
           │                            │
           │  I²C1，400 kHz             │
           │  4 根线：VCC/GND/SCL/SDA    │
           │  PB6=SCL  PB7=SDA          │
           └────────────┬───────────────┘
                        ▼
            ┌───────────────────────┐
            │ STM32F103（同一条总线）│
            │  两个地址不冲突        │
            │  0x68 ≠ 0x36          │
            └───────────┬───────────┘
                        │ USB（和命令共用，双向）
                        ▼
            ┌───────────────────────┐
            │ ArmHost 3D 视图        │
            │  0x10 帧，50 Hz        │
            └───────────────────────┘
```

| | MPU6050 | AS5600 |
|---|---|---|
| 装在 | **小臂 / 末端** | **底座转轴** |
| 测什么 | 相对水平的倾角（pitch） | 转轴绝对角度 |
| 地址 | 0x68（HAL 里是 0xD0） | 0x36 |
| 物理上在控制环里 | ❌ 只上报 | ✅ **是闭环的反馈** |
| 坏了会怎样 | `move_start()` 直接 return（全停） | 底座那路失去闭环 → 降级，bit4 上报 |
| 为什么需要它 | 任务书 T4 要求 | **360° 连续舵机内部没有位置反馈** |

> **360° 舵机为什么必须配编码器**：普通 SG90 靠输出轴上的电位器知道自己转到哪；
> 360° 连续舵机把电位器换成了固定分压，**只认速度不认位置**。
> 所以要外加 AS5600 补这个信息 —— 这就是 `arm_joint.c` 里"底座走闭环、其余直通"的物理来源。

### A-4 电源链路（能量流，和数据流完全分开）

```text
12V 适配器
   │
   ├──→ MP1584 降压 ──→ 5.0V ──→ 保险丝 3A
   │                              │
   │                              ├──→ 舵机 ×4（峰值 2.6A）
   │                              │     ⚠️ 不经过洞洞板
   │                              │
   │                              └──→ 跳线帽 ──→ Blue Pill 5V
   │                                                │
   │                                                └──→ 板载 LDO
   │                                                      │
   │                                                      └──→ 3.3V
   │                                                            │
   │                                                            ├──→ MPU6050 VCC
   │                                                            └──→ AS5600 VCC
   │
   └──→ GND（和 5V 侧共地，非隔离）
                 │
                 └──→ 所有 GND 汇到一点（星形）
```

**MP1584 参数**：输入 4.5–28 V，输出 0.8–25 V，**峰值 3 A / 连续 1.5 A**。
4×SG90 轻载约 1.2 A；一个堵转 → +0.65~0.7 A → 1.9 A，**超过连续值**，所以：
不要让四个关节同时顶到极限。

### A-5 三条流的分界

| 流 | 载体 | 能不能混 |
|---|---|---|
| 数据 | USB / I²C / PWM 方波 | 可以和电源同板 |
| 能量 | 12V / 5V 粗线 | **不能和数据线并行太长**（干扰） |
| 机械 | 齿轮、连杆 | 只受能量驱动 |

### B-4 母线走法：只有 GND 需要走全板

| 母线 | 走多远 | 为什么 |
|---|---|---|
| **GND** | **全板**：x=11 竖线 y 1→35，外加顶边 y=1 横向汇合 | 所有器件都要共地，没有例外 |
| **5V** | **只有 4 cm**（保险丝 → 跳线帽 → pill） | 舵机 5V 从 MP1584 端子直接飞出去，**不上板** |
| **3.3V** | **两段短线**（pill → 两个模块） | 只有逻辑用 |

```text
        ┌────────────────────────────────────┐
   5V ──┤ 保险丝 ──┬──→ 20AWG 粗线 ──→ 舵机×4  │  ← 不经过板
        │          │                          │
        │          └──→ 跳线帽 ──→ pill 5V     │  ← 板上这 4cm
        └────────────────────────────────────┘

   GND ────●───●───●───●───●───●───●───●───  ← 全板母线（裸铜线）
           │   │   │   │   │   │   │   │
          pill MPU AS5 舵机J1-J4 端子  ST-Link
```

**为什么舵机 5V 不上板**：4×650 mA 堵转峰值 → 2.6 A。
洞洞板焊盘接触电阻 + 细线压降，会让舵机抖动、甚至把 MCU 拉到复位。

### B-6 焊接顺序（先矮后高，先地后电）

```text
① 焊所有排针和端子（最低的）
      ↓
② 焊 GND 母线：一根裸铜线从 x11,y1 拉到 x11,y35
   再用细线把顶边 y=1 从 x1 连到 x11（横向汇合）
      ↓
③ 焊 5V 母线：只有 4cm，保险丝 → 跳线帽
      ↓
④ 焊 3.3V 两段：pill 3.3V → MPU6050 → AS5600 排针
      ↓
⑤ 焊 4 根信号线：PA0–PA3 → 舵机排针 x14（最细，24AWG）
      ↓
⑥ 焊 I²C 两根：PB6/PB7 → MPU6050（尽量 < 10 cm）
      ↓
⑦ 插 Blue Pill，插模块（母排可拔）
```

**别一根一根飞线。** 焊到第 6 根就开始乱，而且虚焊查不出来。
**GND 用一根裸铜线做母线**，所有 GND 就近搭上去 —— 这是洞洞板最重要的技巧。

### B-7 上电前 4 项（万用表到了就能做）

| # | 量什么 | 合格 | 不正常 |
|---|---|---|---|
| 1 | 5V 母线 ↔ GND | > 100 Ω 且稳定 | < 10 Ω = 短路，别上电 |
| 2 | 3.3V ↔ GND | > 100 Ω | 同上 |
| 3 | 12V 输入正负 | > 1 kΩ | 接近 0 = 反接 |
| 4 | **空载**上电，量 MP1584 输出 | 5.00 ± 0.05 V | 偏了调电位器 |

**顺序不能反**：调压 → 插 pill → 接舵机。

### B-8 三个必须实测的物理细节

| # | 确认什么 | 为什么 |
|---|---|---|
| 1 | **MPU6050 模块的针距** | GY-521 是 1×8 排针（20 mm），别的模块可能 2×4。B-3 的孔位按实物微调 |
| 2 | **Blue Pill 两排间距** | 标准 0.6 英寸 = 15.24 mm = **6 个孔**。买回来先量再焊母排 |
| 3 | **舵机线序** | SG90 通常 橙=信号 红=5V 棕=GND，杂牌有反的。**万用表量红黑，别信颜色** |

## 3. 常见故障对照表（按住不动的机械臂最常撞的）

| 现象 | 大概率的物理原因 | 先查哪 |
|---|---|---|
| 插 USB 电脑没反应 | 线只焊了电源两根 / USB 口虚焊 | 换线、换口、看设备管理器 |
| 能枚举但 COM 打不开 | 上一轮进程没退 / 驱动残留 | 关掉 ArmHost 再插拔 |
| 舵机不动，但有轻微嗡嗡声 | 信号线没接 / 信号接到了别的脚 | 量 PA0–PA3 到排针通不通 |
| 舵机抖动、MCU 偶发复位 | 5V 走了细线，压降大 | 量 5V 母线带载时的电压 |
| 上电后 MP1584 发烫 | 输出短路 / 负载过大 | 断电量 5V↔GND 电阻 |
| I²C 读不到 MPU6050 | 接了 5V / 上拉被拉到 5V / SCL SDA 接反 | 量 PB6/PB7 是否有 3.3V 上拉 |
| 手一碰舵机齿轮就重启 | 地线太细 / 星形接地没做 | 加粗 GND、检查共地点 |
| 3D 视图不动但舵机在动 | 状态帧没发出去（USB 断了） | 看 ArmHost 有没有在收 0x10 |

## 5. 与代码的对应关系

| 这件事 | 代码里在哪 | 说明 |
|---|---|---|
| 脉宽范围 500–2500 µs | `arm_cfg.h` 的 `SERVO_US_NOMINAL_MIN/MAX` | **唯一**的硬钳位 |
| 4 个关节的引脚/角度范围 | `arm_cfg.c` 的 `g_arm_joint[]` | 标定后只改这里 |
| 角度 → 脉宽 → CCR | `arm_pwm.c` | 定时器 PSC=35, ARR=39999 → 0.5µs/step |
| 底座走闭环 | `arm_joint.c` + `as5600.c` | J1 现在是 `ARM_JOINT_POS`，到货后改 `ARM_JOINT_VEL` |
| 传感器读数上报 | `proto_app.c` 的 `send_status()` | 0x10 帧，50 Hz |
| 传感器故障联锁 | `mpu6050_faulted()` → `s_sensor_fault` | 故障时 `move_start()` 直接 return |

## 附：为什么两张图不能合成一张

| | 图 A（实物数据流） | 图 B（接线布局） |
|---|---|---|
| 回答 | **值沿什么路径走、每段多久** | **哪个孔接哪根线** |
| 边表示 | 数据/能量/机械的传递 | 导线连接 |
| 会变吗 | 几乎不变 | 换模块就要改 |
| 用来看 | 命令为什么没生效、延迟在哪 | 焊的时候照着做 |

图 A 里最该记住的数字：**代码只占 1 ms，机械占 100 ms。**
所以插补器要解决的是"摊平速度"，不是"加快响应"。
