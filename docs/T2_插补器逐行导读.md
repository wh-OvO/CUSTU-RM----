# T2 插补器逐行导读

> 面向：能看懂 C 语法，但没写过运动控制的人。
> 对照源码：`Core/Src/proto_app.c`（插补器本体）、`Core/Src/arm_joint.c`（执行层）、`Core/Src/arm_cfg.c`（参数表）。
> 建议按 §2 → §3 → §4 → §5 的顺序读，§6 起是验证与扩展。

---

## 0. 一句话

**插补器 = 把"从 A 瞬移到 B"拆成"用 duration 毫秒，每 20ms 走一小步，从 A 走到 B"。**

没有它，舵机收到新脉宽会**立刻全速**冲向目标：四个关节同时全速 → 电流叠加 → USB 掉电、机械冲击、夹爪里的东西被甩掉。
有了它，可以控制"多久到"、"走得多快"，而且轨迹连续。

---

## 1. 先搞清三层的分工

```
协议层 proto_app.c      "我要去 30°"          ← 只关心角度
    ↓ 每 20ms 给一个中间点
执行层 arm_joint.c      "这一拍该在哪 / 该多快"  ← 区分位置型 / 速度型
    ↓
硬件层 arm_pwm.c        "CCR 写多少"          ← 只认 µs
```

**关键约定**：换算（度 → µs）只发生在最底层。插补器里全是"度"，不出现 µs。
这样上层改算法不会碰到定时器，底层改定时器不会影响算法。

---

## 2. 一拍里到底发生了什么

`proto_app_poll()` 每 20ms 跑一次，顺序是**写死的**（`proto_app.c:810~873`）：

```c
① while (link_poll(&fr) == 1) dispatch(&fr);   // 收帧：可能改 s_tgt_x10，可能调 move_start
② 上电自动回零检查                             // proto_app.c:829
③ if (now - s_ms_report >= 20ms) {
     interp_tick(now);        // ← 算出本拍四个关节的目标角
     arm_joint_tick(now);     // ← 闭环关节追目标（现在没有闭环关节，空转）
     send_status(now);        // ← 上报 0x10
   }
④ 发 0x23 心跳
⑤ 判超时
```

**为什么 ③ 里必须是"先 interp 再 report"**：`send_status()` 读的是 `arm_joint_get_deg()`，
如果顺序反了，上报的 `act` 比实际慢一拍，ArmHost 的 3D 视图会明显滞后（20ms × 采样点，肉眼可见）。

**为什么 ① 必须在 ③ 之前**：这一拍收到的 `0x20` 要**当拍生效**，不能等到下一拍。

## 3. 变量表（先认清谁是谁）

`proto_app.c:71~99`：

| 变量 | 单位 | 谁写 | 干什么 |
|---|---|---|---|
| `s_tgt_x10[4]` | **0.1°** | 协议层 | 最终目标角，**唯一的目标真值** |
| `s_q_from[4]` | 度 | 插补器 | 本段**起点**，开始走那一刻的快照 |
| `s_dur_ms` | ms | 插补器 | 本段总时长 |
| `s_ms_move0` | ms | 插补器 | 本段开始时刻（`HAL_GetTick()`） |
| `s_moving` | — | 插补器 | 1 = 正在插补 |

### 为什么 `s_tgt_x10` 用 0.1°，`s_q_from` 却用度？

不是笔误，是**两种不同的东西**：

- **0.1° 是协议线上的格式**。`0x20` 载荷里就是 `int16` 的 0.1°，所以存成 `s_tgt_x10` 才能原样对上协议。
- **度是物理量**。插补器算的是真实角度，用度最自然。

**换算只发生在插补器这一处**（`/ 10.0f`），别的地方各自保持本来的单位。
这是防止"单位污染"的常用手法：一旦混着用，某个函数少除一次 10，现象是**舵机走 10 倍**，极难查。

## 4. `move_start()` —— 一场运动的起跑（`proto_app.c:235`）

### 4.1 先拦故障

```c
if ((s_fault != 0u) || (s_sensor_fault != 0u)) return;
```

急停或传感器失效时，**新动作一律拒绝**。这是"故障态不动"的第一道闸。
（第二道在 `interp_tick` 外面，第三道在 `arm_joint_hold_position`。）

### 4.2 快照起点 —— 用**实际位置**，不是上一个目标

```c
for (j...) {
  s_q_from[j] = arm_joint_get_deg(j);   // 此刻实际在哪
  arm_joint_set_manual(j, 0u);          // 退出 0x31 手动模式
  arm_output_enable(j, 1u);             // 恢复之前可能关掉的输出
}
```

**这是整个插补器最重要的一行**。

假设上一段是 90° → 45°，走到 70° 时你突然发 120°：

| 起点取法 | 结果 |
|---|---|
| 取上一个目标（45°） | 先**跳回** 45°，再往 120° 走 → 机械上"抽"一下，冲击电流 |
| **取实际位置（70°）** | 从 70° 平滑续接往 120° 走 → 连续 |

这叫**打断续接**。没有它，连续发目标（比如手柄摇杆）会一顿一顿的。

`arm_joint_set_manual(j, 0u)` 的作用：如果之前用 `0x31` 单独推过某一路舵机，那一路处于"手动模式"，
闭环不接管。这里统一收回，保证插补能控制全部四路。

### 4.3 `duration == 0` 的特判

```c
if (dur_ms == 0u) {
  for (j...) arm_joint_set_deg(j, s_tgt_x10[j] / 10.0f);   // 一步到位
  s_moving = 0u;
  return;
}
```

**两个理由**：

1. **除零**。下面 `interp_tick` 里要算 `s = t / dur`，`dur = 0` 就是 `inf`。
2. **语义**。`duration = 0` 在协议里表示"立刻到位"，等价于没有插补器的老行为。
   保留这个语义，才能做 A/B 对比：同样的帧，`duration=0` 是跳变，`duration=2000` 是平滑。

### 4.4 正常路径

```c
s_dur_ms   = dur_ms;
s_ms_move0 = HAL_GetTick();
s_moving   = 1u;
```

只记三个数，**不在这里算任何点**。真正的计算全在 `interp_tick` 里。
这样"开始"和"推进"完全解耦——`interp_tick` 只看这三个数，不管是谁启动的（`0x20`、回零、上电自动回零，都是同一条路）。

## 5. `interp_tick()` —— 每一拍算一个点（`proto_app.c:273`）

### 5.1 核心就三行

```c
t = now - s_ms_move0;                    // 已经走了多久
s = (float)t / (float)s_dur_ms;          // 归一化进度 0 → 1
q = s_q_from[j] + (q_to - s_q_from[j]) * s;   // 线性插值
```

`s` 是**归一化进度**：0 = 刚起步，1 = 到位。四个关节共用同一个 `s`，
所以**同时出发、同时到达**。这就是"多轴联动"的全部秘密。

### 5.2 三个必须注意的细节

#### ① 夹住 `t >= dur`

```c
if (t >= (uint32_t)s_dur_ms) {
  t        = (uint32_t)s_dur_ms;
  s_moving = 0u;                    // ← 在这一拍就清掉
}
```

不夹的话：

- `s` 会大于 1 → 角度**冲过头**（比如目标 30°，实际算到 28°）
- `s_moving` 永远清不掉 → 插补器永久运行，后面每拍都在算一堆没用的数

注意 `s_moving = 0u` 是**在夹住那一拍清的**，但 `q` 仍然会算出来（用 `s = 1`），
所以最后一拍输出的正好是终点 `q_to`，不会少一步。

#### ② 两个 `(float)` 强转，一个都不能省

```c
s = (float)t / (float)s_dur_ms;
```

如果写成 `t / s_dur_ms`（两个都是整数）：

- C 的整数除法**向零取整**
- `400 / 800` = **0**
- 于是 `s` 一直是 0 → `q` 一直等于起点 → **舵机纹丝不动**
- 等 `t >= dur` 那一拍，`s` 整个变成 1 → **突然跳到终点**

现象就是"先不动，到时间猛地一抽"。源码里专门写了注释（`proto_app.c:293`），因为这坑踩过一次。

#### ③ 速度 `v` 只给闭环关节用

```c
if (s_moving != 0u)
  v = (q_to - s_q_from[j]) * 1000.0f / (float)s_dur_ms;   // 度/秒
arm_joint_set_traj(j, q, v);
```

`v` 是**本段的理论速度**。线性插补下速度恒定，正好可以直接当前馈量（见 §7）。
`* 1000.0f` 是把"每毫秒"换成"每秒"。

## 6. 亲手算一遍：J4 从 90° → 30°，`duration = 1000ms`

条件：`s_q_from = 90`，`q_to = 30`，`dur = 1000`，节拍 20ms。

| t (ms) | s = t/1000 | q = 90 + (30−90)·s | v (°/s) |
|---|---|---|---|
| 0 | 0.00 | 90.0 | −60 |
| 100 | 0.10 | 84.0 | −60 |
| 200 | 0.20 | 78.0 | −60 |
| 400 | 0.40 | 66.0 | −60 |
| 500 | 0.50 | 60.0 | −60 |
| 600 | 0.60 | 54.0 | −60 |
| 800 | 0.80 | 42.0 | −60 |
| 1000 | 1.00 | **30.0** | 0 |

**三个结论**：

1. **角度曲线是一条直线**（时间-角度图上就是斜线）
2. **速度恒定 −60°/s** → ArmHost 的「角速度曲线」应该是一条**水平的直线**，约 −60
3. 位置型关节走的是 `arm_set_deg()`，实际舵机有机械延迟，**画出来会略微滞后**，这是正常的

> ⚠️ **别去找梯形**。`proto_app.c:367` 写明 `profile: 0 = 线性插补。梯形 / S 曲线还没做`。
> 现在角速度是**平的**，不是梯形。看到平台才是对的。

## 7. 前馈速度 `v` 是给谁的，为什么要它

### 7.1 现在没人用

`arm_joint_set_traj()`（`arm_joint.c:158`）把 `v` 存进 `s_ff_dps[joint]`：

```c
s_tgt_deg[joint] = deg;
s_ff_dps[joint]  = v_dps;

if (kind == ARM_JOINT_POS) {
  arm_set_deg(joint, deg);    // 位置型：立即生效，v 用不上
}
// 速度型：只记下目标，等 arm_joint_tick() 去追
```

而 `arm_cfg.c:58` 现在四个关节**全是 `ARM_JOINT_POS`**，所以：

- `arm_joint_tick()` 里的 `vel_tick()` 一次都不会跑
- `s_ff_dps` 存了但没人读

**等 360° 舵机 + AS5600 到位，把 J1 改成 `ARM_JOINT_VEL`，这条链才活。**

### 7.2 为什么要前馈（这是控制上的关键）

底座是 360° 连续舵机，只能控制**转速**，位置靠 AS5600 读回来闭环。

如果只用一个 P 控制器：

```
u = Kp × (目标 − 实际)
```

追一个**匀速**目标时，P 会稳定在一个**恒定的滞后**上：必须一直有误差，才有输出驱动它转。
误差稳态值 = 速度 / Kp。想走得快，就必然落后得多。

加上前馈：

```
u = 前馈(v) + Kp × 误差
```

前馈直接告诉舵机"要做到这个速度该给多少 µs"，P 只负责修**剩下的**小误差。
稳态误差接近 0。

`arm_joint.c:105`：`u_ff = s_ff_dps[joint] * c->us_per_dps;`
——把"度/秒"乘上"每 °/s 对应多少 µs"，变成 µs 直接加到脉宽上。

**这也解释了为什么插补器要算 `v`**：它知道这一段的斜率，这是前馈的唯一来源。

## 8. 故障怎么打断插补

三处，缺一不可：

| 位置 | 代码 | 作用 |
|---|---|---|
| `move_start()` 开头 | `if (s_fault \|\| s_sensor_fault) return;` | 故障态**不接受**新动作 |
| `on_estop()`（`proto_app.c:450`） | `s_moving = 0u; arm_joint_hold_position();` | 急停立刻**停插补** + 底座原地保持 |
| `proto_app_poll()`（`proto_app.c:800`） | 传感器失效时 `s_moving = 0u;` | MPU6050 掉线也停 |

**为什么急停要单独写 `s_moving = 0u`，不能只置故障位**：
插补是 20ms 一拍推进的，只置故障位的话，**下一拍还会再走一步**才停。20ms 内舵机全速能走好几度。

`arm_joint_hold_position()`（`arm_joint.c:237`）做的事很聪明：
把底座目标改成"我现在实际在哪" → 闭环误差归零 → 原地不动。
位置型关节不用处理，因为 CCR 不被改写，舵机自己就停住了。

## 9. 上电自动回零为什么放在 `dispatch` 之后（`proto_app.c:829`）

```c
while (link_poll(&fr) == 1) dispatch(&fr);   // ← 先收帧
...
if (s_boot_home_pending && (now - s_ms_boot) >= 500) { ... move_start(ARM_HOMING_MS); }
```

如果放在 `dispatch` **之前**：

- 这一拍刚好收到 `0x20` → 先执行了回零（`move_start`），再处理 `0x20`（又 `move_start` 一次）
- 结果是**多走一段**，或者两个 `move_start` 互相打架

放后面就自动解决了：`dispatch` 里的 `on_target()` 会把 `s_boot_home_pending` 清 0，
轮到回零检查时条件已不成立，直接跳过。

**这是"用顺序代替标志位"的典型手法**：不用额外写"是否冲突"的判断，靠执行次序天然保证优先级（人的指令 > 自动流程）。

## 10. 梯形 / S 曲线怎么加（T2 唯一的真缺口）

### 10.1 现在的问题

线性插补下，**起停瞬间速度是突变**的：

```
t=0   速度 0  →  瞬间变成 −60°/s      ← 加速度无穷大
```

对舵机意味着：启动瞬间电流冲击、停止瞬间机械冲击。速度越大越明显。

### 10.2 加在哪：只改一行

`interp_tick()` 里：

```c
s = (float)t / (float)s_dur_ms;        // ← 就是这一行
```

换成：

```c
s = profile_s(profile, t, s_dur_ms);   // 返回 0→1 的归一化进度
```

**其它代码一行都不用动**，因为所有下游只依赖"`s` 从 0 单调走到 1"。

### 10.3 梯形的三个约束

不管用什么曲线，必须满足：

| 约束 | 为什么 |
|---|---|
| `s(0) = 0` | 起点必须是起点 |
| `s(dur) = 1` | **终点必须精确到位**，否则永远差一点 |
| `s` 单调不减 | 不能中途倒退 |

梯形速度曲线对应的是**分段二次**的 `s`：

```
设加速时间 ta、减速时间 td、总时长 T、总位移 D
v_max = D / (T − ta/2 − td/2)

t < ta:        s = 0.5·(v_max/ta)·t² / D
ta ≤ t < T−td: s = (v_max·(t − ta/2)) / D
t ≥ T−td:      s = 1 − 0.5·(v_max/td)·(T−t)² / D
```

S 曲线就是把加速度再平滑一次（加加速度 jerk 有限），公式更复杂，但落点同样是那一行 `s = ...`。

### 10.4 `profile` 字节已经留好了

`0x20` 载荷第 11 字节是 `profile`（`proto_app.c:365`），现在被 `(void)profile;` 丢掉了。
加梯形时用它选档：`0 = 线性`、`1 = 梯形`、`2 = S 曲线`。
未知值**静默按线性跑**——降级比报错稳，至少手臂还在动。

## 11. 常见误解

| 误解 | 实际 |
|---|---|
| "插补器在控制舵机" | 它只产生**角度**。真正写 CCR 的是 `arm_pwm.c` |
| "`duration` 就是舵机走完的时间" | 是**指令下发的时间**。舵机有机械延迟，实际到位略晚 |
| "四个关节可以设不同时长" | **不行**。共用同一个 `s`，这是"同时到"的代价。要分开就得每关节一个 `s` |
| "`act` 是实测角度" | 位置型是 **CCR 反算**，不是实测。只有底座（VEL + AS5600）才是真值 |
| "改 `duration` 会改终点" | 不会。终点永远是 `s_tgt_x10`，`duration` 只改**走的快慢** |

## 13. 上手验证（只接 J4 就行）

| 步骤 | 操作 | 该看到什么 |
|---|---|---|
| 1 | 用 `0x31` 把 J4 推到 90° | 舵机到中位 |
| 2 | 发 `0x20`：J4 目标 30°，`duration = 2000` | 2 秒内平滑走完，**角速度曲线是一条 −30°/s 的平线** |
| 3 | 改 `duration = 500` | 同样 60° 行程，速度变成 −120°/s，**线更高，但依然平** |
| 4 | 改 `duration = 0` | **瞬间跳过去**，角速度曲线上是一根竖线 |
| 5 | 走到一半（1 秒时）发新目标 150° | 从当前位置**平滑续接**，不跳回 |
| 6 | 走到一半按急停 | **立刻停**，不是走完这一段 |

第 5、6 步是这套设计最值得看的两处。
