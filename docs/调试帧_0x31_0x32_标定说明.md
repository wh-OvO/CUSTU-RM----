# 0x31 / 0x32 调试帧说明（舵机标定用）

> 对应代码：`Core/Inc/proto.h`（常量）、`Core/Src/proto_app.c`（处理函数）、
> `Core/Src/arm_pwm.c`（底层三个标定接口）
> 对应上位机：ArmHost v1.2 的「调试模式」页

---

## 0. 一句话

`0x31` 让上位机**直接指定某一路的脉宽**，`0x32` 把**芯片里真实的脉宽读回来**。
两帧配合，标定就从"改代码 → 编译 → 烧录"变成"点一下按钮"。

---

## 1. 这两帧不在任务书的必做范围里

任务书 1.5 / 协议正本 §4 只规定了 `0x10 / 0x20 / 0x21 / 0x22 / 0x23 / 0x24` 六种帧。
`0x30 ~ 0x33` 是 v1.1 之后加的**扩展帧**，属于"有了更好"。

那为什么还要写？算一笔账：

| 做法 | 标定一只舵机要多少次编译 | 四只 × 全程扫描 |
|---|---|---|
| 改代码重烧 | 每换一个脉宽 1 次，约 40 秒 | 几十个点 → **半天以上** |
| 用 0x31 | **0 次** | 几分钟 |

**它不增加验收分，但省下来的时间是给 T2/T4 的。** 这就是做它的全部理由。

---

## 2. 钳位只剩一层：500 ~ 2500 µs

工程里现在**只有一层**脉宽钳位：

| 层级 | 范围 | 在哪 | 什么时候生效 |
|---|---|---|---|
| 舵机可接受范围 | **500 ~ 2500 µs** | `arm_cfg.h` 的 `SERVO_US_NOMINAL_MIN/MAX` | `arm_set_us()` / `arm_deg_to_us()` 末尾 |
| 标定表映射 | 由 `g_arm_joint[]` 决定 | `arm_cfg.c` | 每次角度换算 |

### 2026-11-09 删掉了原来的"安全窗"（600 / 2400）

那一对数字是我一开始瞎填的占位值，本意是"怕烧舵机，先收着点"。删掉的理由有三条：

**① 它在正常控制里一次都不会触发。** `arm_deg_to_us()` 先把角度夹进
`[deg_min, deg_max]`，再线性插值 —— 算出来的脉宽天然落在标定表两个端点之间。
所以 600/2400 永远咬不到。

**② 它只在标定表写错时才咬人，而那时它咬得没有意义。** 表错了，你看到的现象是
"发 180° 舵机只走了一点点"，然后你会去查映射公式，而不是想到"被一个安全窗夹住了"。
**一个只在故障时才现身的保护，本身就是新的故障源。**

**③ 它和标定冲突。** 标定的任务是找出真实机械限位。如果 600/2400 挡在外面，
你不管发 500 还是 2500，舵机永远只在 600~2400 之间动 —— 真实行程永远测不出来。

### 代价，说清楚

删掉之后，**`arm_cfg.c` 的标定表就是唯一的防线**。表里端点写得太贴机械限位，
温度一变、齿轮一点磨损，就可能顶死堵转。SG90 堵转电流约 650~700 mA，
会发烫、会齿轮打齿。

所以规矩是：**标定测出来的两个端点，各往回收 40~50µs 再填进表里。**
另外，标定时手指放在电源开关上 —— 听到"咯咯"打齿声，或者舵机臂不动了还在嗡嗡响，
立刻断电。

### 为什么 500 / 2500 留着

这不是"我猜的安全范围"，是任务书 1.5 明写的脉宽范围（"500～2500µs"），
也是 SG90 手册的数字。删了它，一个手误就能把 3000µs 发进 CCR。

## 3. `0x31` 帧格式（上位机 → 设备）

```
┌──────┬──────┬──────┬──────────────────────────────┬──────┐
│ 0xA5 │ 0x31 │ 0x04 │  载荷 4 字节                 │ CRC8 │
└──────┴──────┴──────┴──────────────────────────────┴──────┘
```

载荷 4 字节，**小端**：

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `servo` | uint8 | 关节号 0~3（0=J1 底座 … 3=J4 夹爪），≥4 直接丢弃 |
| 1 | `pulse` | uint16 | 脉宽 µs，低字节在前；越界按 500/2500 钳位 |
| 3 | `flags` | uint8 | 见下表 |

`flags` 位定义：

| 位 | 名字 | 含义 | 本工程实现 |
|---|---|---|---|
| bit0 | 输出使能 | 1 = 该通道继续输出；0 = 停该通道（舵机卸力） | ✅ 已实现 |
| bit1 | 其余舵机保持 | 1 = 只动这一路 | ✅ **无条件满足**，见下 |

**关于 bit1**：我们还没有插补器（T2 未做），四路 CCR 只有被显式写入才会变，
不存在"动一路把别的路带跑"的可能。所以这一位发 0 还是 1，行为完全一样。
等 T2 加上插补后，这里要改成真的冻结其余通道，注释在 `on_pulse_set()` 里。

**设备不回显 `0x31`。** 想知道生效没有，用 `0x32` 读。

## 4. `0x32` 帧格式

### 查询（上位机 → 设备，1 字节）

```
A5 32 01 01 94
         ↑  ↑
         │  CRC
         └─ 载荷内容无所谓，习惯填 0x01 表示"请回读"
```

### 应答（设备 → 上位机，9 字节）

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `p1` | uint16 | J1 当前脉宽 µs |
| 2 | `p2` | uint16 | J2 |
| 4 | `p3` | uint16 | J3 |
| 6 | `p4` | uint16 | J4 |
| 8 | `status` | uint8 | 见下 |

> ⚠️ **这个 `status` 和 `0x10` 帧里的 `status` 完全没关系**，位定义不同，
> 千万别混着看。

`status` 位定义：

| 位 | 名字 | 含义 |
|---|---|---|
| bit0 | 调试中 | 最近收到过 `0x31`（收到 `0x20` 或 `0x21` 后清除） |
| bit1 | 故障态 | 急停中，此时 `0x31` 会被拒绝 |
| bit2~7 | 保留 | 恒 0 |

## 5. 固件里的调用链（扒源码就从这里入手）

### `0x31` 走的路

```
USB 中断收到字节
  └─ CDC_Receive_FS()                  USB_DEVICE/App/usbd_cdc_if.c
       └─ link_poll()                  Core/Src/proto_link.c     ← 环形缓冲 + 解帧
            └─ proto_app_poll()        Core/Src/proto_app.c      ← 主循环里被调用
                 └─ dispatch()         switch(fr->type) 分派
                      └─ on_pulse_set()                    ★ 应用层
                           ├─ arm_set_us()                  Core/Src/arm_pwm.c
                           │    └─ arm_write_ccr()
                           │         └─ __HAL_TIM_SET_COMPARE(&htim2, ch, ccr)
                           └─ arm_output_enable()
                                └─ HAL_TIM_PWM_Start / Stop
```

### `0x32` 走的路

```
on_pulse_get()
  ├─ arm_get_us(j)                    ×4
  │    └─ __HAL_TIM_GET_COMPARE(&htim2, ch)
  │         └─ ARM_PWM_CCR_TO_US()    ← ÷2，因为 1 个计数 = 0.5µs
  └─ link_send_frame(PROTO_T_PULSE_GET, pl, 9)
```

**注意 `arm_get_us()` 是读寄存器，不是读软件变量。**
所以它反映的是"芯片现在真的在输出的值"——
如果你同时还在发 `0x20`，两边会打架，读回来的就不是你刚写的那个数。

## 6. 三条安全边界（评审会问的那种）

### ① 故障态拒绝 `0x31`

```c
if (s_fault != 0u) { return; }
```

急停的语义是"谁都别再动"。如果 `0x31` 能绕过去，急停就是个摆设 ——
一个上位机 bug 就能把手臂一路捅到极限。要恢复必须先发 `0x21 = 3` 清故障。

### ② 先写 CCR，再开输出

```c
arm_set_us(servo, us);
arm_output_enable(servo, en);
```

顺序反过来的话，通道会按寄存器里的**旧值**先输出一小段，舵机"抖一下"。
标定时这一下很容易被人误判成"已经到限位了"。

### ③ 从标定模式退出时恢复输出

`apply_targets()` 里每一路都先 `arm_output_enable(j, 1)` 再写角度。
因为标定时可能用 `flags.bit0 = 0` 把某一路关掉过，
如果回到正常控制不恢复，"下发目标没反应"会非常难查。

## 7. 标定流程（四只舵机，每只 6 步）

前置条件（缺一不可）：

- [ ] 舵机**独立 5V 供电**，与主控共地
- [ ] 上位机已连上，`0x32` 能读到数
- [ ] 舵机盘上粘了一根纸指针，旁边有量角器或手机录像
- [ ] **手放在电源开关上**

对每一只（以 J4 为例，servo=3）：

| 步 | 动作 | 记什么 |
|---|---|---|
| 1 | 发 `0x31` J4 = 1500µs，flags=3 | 这是不是大致的中位？不是的话记下实际中位 |
| 2 | 每次 −50µs 往下扫（1450 → 1400 → …） | **指针停住不动的那个值** = 下限机械位 |
| 3 | 从停住的值往回退 40~50µs | 这就是 `us_at_deg_min` 的值（必须留余量） |
| 4 | 每次 +50µs 往上扫（1550 → 1600 → …） | **指针停住不动的那个值** = 上限机械位 |
| 5 | 同样往回退 40~50µs | `us_at_deg_max` 的值（必须留余量） |
| 6 | 在两端之间取中，发过去确认机械臂居中 | `deg_home` 对应的脉宽 |

> **判断"到限位"的两个信号**：① 指针不再移动；② 舵机开始持续"嗡嗡"响（堵转）。
> 看到②要**立刻**回退，不要停在上面观察。

四只都做完，把结果填回 `Core/Src/arm_cfg.c`。

## 8. 标定结果怎么填回 `arm_cfg.c`

每个关节一条：

```c
{ "J1 底座", deg_min, deg_max, deg_home, us_at_deg_min, us_at_deg_max }
```

- `deg_min` / `deg_max`：**逻辑角度**，你自己定的坐标系（比如 0~180）。
  它只是"刻度"，不是舵机属性。
- `us_at_deg_min` / `us_at_deg_max`：对应这两个逻辑角度的**实测脉宽**。
- `deg_home`：上电归位角度，要在 `[deg_min, deg_max]` 之间。

映射是线性的，公式在 `arm_pwm.c` 顶部注释里：

```
us = us_at_deg_min + (deg − deg_min) × (us_at_deg_max − us_at_deg_min) ÷ (deg_max − deg_min)
```

**举个完整的例子**（假设实测 J4：下限机械位 560µs，上限机械位 2420µs）：

```c
/* 留 40µs 余量，逻辑行程定 0~180° */
{ "J4 夹爪", 0, 180, 90, 600, 2380 }
```

验证：`deg=90` → `us = 600 + 90 × (2380−600) ÷ 180 = 600 + 890 = 1490µs`，
和实测中位（约 1500）对得上，说明填对了。

## 9. 可以直接粘进串口助手的示例帧

发之前确认：**串口助手不能同时占着 ArmHost 的端口**，两者只能有一个。

| 目的 | 字节 |
|---|---|
| 读回四路脉宽 | `A5 32 01 01 94` |
| J4 → 1000µs（输出开） | `A5 31 04 03 E8 03 03 11` |
| J4 → 500µs（下边界） | `A5 31 04 03 F4 01 03 63` |
| J4 → 2500µs | `A5 31 04 03 C4 09 03 2A` |
| J4 → 1500µs（回中位） | `A5 31 04 03 DC 05 03 25` |
| J4 → 1000µs（**关掉该路输出**） | `A5 31 04 03 E8 03 01 1F` |
| J1 → 1500µs | `A5 31 04 00 DC 05 03 1F` |
| 0x32 应答长这样（全 1500，调试中） | `A5 32 09 DC 05 DC 05 DC 05 DC 05 01 0A` |

`500` 和 `2500` 这两条是**边界验证**：读回来正好是 500 / 2500，
说明钳位在手册范围内已经放开到底，标定才能一直扫到机械限位。

## 10. 常见问题

**Q: 发了 `0x31`，舵机纹丝不动？**
① `flags` 的 bit0 是不是 0（关输出了）；② 关节号对不对；③ 舵机电源通没通、共地了没；
④ 是不是急停中（发 `0x32` 看 status 的 bit1）。

**Q: `0x32` 读回来的不是我刚发的值？**
最常见的原因是**同时还在发 `0x20`**。`0x20` 会把四路一起重写，
你写 1000、它写回 1500，来回打架。标定时把上位机的"连续下发"关掉。

**Q: 为什么读回值总是 2 的整数倍？**
时基是 2MHz，1 个计数 = 0.5µs，所以 CCR 只能是整数，
换算回 µs 时奇数会落到 .5 —— 代码里用整数除法，会截断成偶数。这是正常现象，
分辨率优于 1µs，满足任务书 1.3 的要求。

**Q: 能不能不加 0x31，直接用 `0x20` 标定？**
能，但很痛苦：`0x20` 走的是标定表映射，而标定表正是待标定的东西。
逻辑上就绕回去了。所以标定必须从 `0x31` 这条"裸脉宽"通道进。
