# T1 角度↔脉宽映射 · 代码说明

> 写给"会 C、但第一次碰 STM32"的人。
> 目标：你能自己把这份代码从头到尾读通，并且知道**要改哪个数字该动哪一行**。
>
> 对应任务书：T1「四路 PWM 独立输出 50Hz，脉宽可调范围覆盖 500～2500µs，步进不大于 2µs；
> 实现角度到脉宽的线性映射，映射参数写在配置文件或宏里，不散落在代码中」。

---

## 1. 这份代码在干什么（一句话）

把"J2 抬到 45°"这种**人能懂的角度**，变成一个 20ms 周期里、高电平持续 1.0ms 的方波，
喂给接在 PA1 上的舵机。

```
你写         arm_set_deg(1, 45.0f)
              ↓  arm_cfg.c 里 J2 的标定参数
            脉宽 = 600 + (45-0) × (2400-600)/(180-0) = 1050 µs
              ↓  CCR = 脉宽 × 2
            往 TIM2->CCR2 写 2100
              ↓  硬件自己跑，CPU 不用管
            PA1 每 20ms 输出一次 1050µs 的高电平
```

---

## 2. 为什么是 20ms / 50Hz —— 从 72MHz 算下来

这是新手最容易卡住的地方：**时钟、预分频、周期**是三个不同的东西。

| 层级 | 谁决定的 | 数值 | 含义 |
|---|---|---|---|
| 系统时钟 | CubeMX 时钟树 | 72 MHz | CPU 和大多数外设的"心跳" |
| APB1 定时器时钟 | APB1 分频 = 2，但定时器时钟 ×2 补偿 | 72 MHz | TIM2 的输入时钟 |
| 计数频率 | `PSC = 35` | 72MHz ÷ (35+1) = **2 MHz** | 计数器每 0.5µs 加 1 |
| PWM 周期 | `ARR = 39999` | (39999+1) × 0.5µs = **20 ms** | 一个完整方波的长度 |
| 高电平长度 | `CCR` | CCR × 0.5µs | 这就是"脉宽" |

所以：

```
CCR = 脉宽(µs) × 2
```

- 1500µs（中位）→ CCR 3000
- 600µs（安全窗下限）→ CCR 1200
- 2400µs（安全窗上限）→ CCR 4800

**分辨率 = 0.5µs/步**，任务书要求"步进不大于 2µs"，我们细 4 倍。

> 注意 `PSC` 和 `ARR` 在 CubeMX 里显示的名字带 "-1"：
> CubeMX 写 `Prescaler = 35`，硬件实际分频是 36。这是 ST 的约定，别自己减 1。

## 3. 文件地图（先看这张表再看代码）

```
Core/Inc/arm_cfg.h      ← 所有可调数字：时基、脉宽安全窗、结构体定义
Core/Src/arm_cfg.c      ← 四个关节的标定表（**标定就是改这个文件**）
Core/Inc/arm_pwm.h      ← 对外 6 个函数
Core/Src/arm_pwm.c      ← 换算实现（线性插值 + 限幅）
Core/Src/main.c         ← 调用方：上电调 arm_init()，主循环里按键
docs/本文件             ← 就是你正在看的
```

调用关系：

```
main()
 └─ MX_TIM2_Init()        ← CubeMX 生成，配 PSC/ARR/4 个通道
 └─ t0_setup()
     └─ arm_init()        ← 本工程：四路先给中位，再 HAL_TIM_PWM_Start()
         └─ arm_set_deg(0..3, deg_home)
             └─ arm_deg_to_us()   ← 线性插值
                 └─ arm_write_ccr()
                     └─ __HAL_TIM_SET_COMPARE(&htim2, CHx, ccr)   ← 写寄存器
```

**为什么 `arm_init()` 要先把 4 路 CCR 都写成中位，再启动 PWM？**

CubeMX 生成的 `MX_TIM2_Init()` 只给 CH1 配了 `Pulse = 3000`，
CH2/CH3/CH4 的 `Pulse` 是 **0**（它复用同一个 `sConfigOC` 结构体，只改 `Pulse` 一次）。
如果你直接 `HAL_TIM_PWM_Start()`，另外三路会以 0% 占空比输出 —— 舵机看到的是"没有信号"，会乱走或者不动。

## 4. 给 STM32 新手的概念对照

| 你熟悉的概念 | STM32 里对应什么 |
|---|---|
| 一个"外设对象" | `TIM_HandleTypeDef htim2`（CubeMX 在 main.c 里定义好的全局变量） |
| 配置结构体 | `htim2.Init.Prescaler` 这些字段，`MX_TIM2_Init()` 里填 |
| 调库函数 | `HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1)` |
| 直接改寄存器 | `__HAL_TIM_SET_COMPARE(&htim2, ch, ccr)` —— 宏，展开就是 `htim2.Instance->CCR1 = ccr` |
| 中断 | `stm32f1xx_it.c` 里的 `TIM3_IRQHandler()` → `HAL_TIM_IRQHandler()` → 你的回调 |

三个必备认知：

1. **`USER CODE BEGIN/END` 之间的东西重新生成也不会丢。** 这个工程所有自己写的代码都在这些块里，
   或者放在 `Core/Src/arm_*.c` 这种 CubeMX 不认识的新文件里。块外面的代码**每次 GENERATE CODE 都会被覆盖**。
2. **`.ioc` 才是配置的真相。** CubeMX 生成的 `MX_xxx_Init()` 是 `.ioc` 的投影。
   改了 `.ioc` 里 TIM2 的 PSC，`arm_cfg.h` 里的 `ARM_PWM_PSC` 也必须跟着改，否则注释和实际对不上。
3. **`%f` 不要用。** newlib-nano 默认不带浮点 printf，写了会打印出空白或乱码。
   本项目所有打印都用整数（角度乘 10 再打）。

## 5. 标定流程（没有示波器、没有逻辑分析仪也能做）

任务书要求"各关节行程与零位须自行标定，以标定为准"。步骤如下，**一次只动一个关节**：

### 5.1 准备

1. 舵机**独立供电**（MP1584 输出 5V），和主控**共地**。绝对不要从板子的 3.3V/5V 取电带舵机。
2. 先只接 J1 一个舵机，其他三路空着（空载不会烧）。
3. 上电顺序：先接共地 → 舵机上电 → 主控上电（任务书 1.4 的硬要求）。

### 5.2 找机械端点（关键是"刚好不顶死"）

在 `main.c` 的 `USER CODE 2` 里临时插一行，用**脉宽**直接驱动，绕过角度换算：

```c
arm_set_us(0, 1500);   /* 先回中位 */
HAL_Delay(1000);
arm_set_us(0, 1600);   /* 每次 +100µs，看舵机往哪边走 */
```

从 1500 开始，每次 ±50µs 试，找到：

- 舵机**刚好**转到机械端点
- 但电机**不发出"嗡嗡"的堵转声**、外壳不烫

记下这两个 µs 值，比如 `780` 和 `2210`。**再各收进 30~50µs** 作为安全余量 → `830` / `2160`。

> 为什么要收：舵机堵转电流是空载的 5~7 倍。四路同时堵转会直接超过 MP1584 的 1.5A 连续能力。

### 5.3 填表

打开 `Core/Src/arm_cfg.c`，改对应关节的 `us_at_deg_min` / `us_at_deg_max`：

```c
{
  .name           = "J1 底座",
  .deg_min        = 0,
  .deg_max        = 180,
  .deg_home       = 90,
  .us_at_deg_min  = 830,      /* ← 实测值 */
  .us_at_deg_max  = 2160,     /* ← 实测值 */
},
```

### 5.4 量行程（可选，但建议做）

用量角器/纸片标记，量一下这两个端点之间实际转了多少度，填进 `deg_min` / `deg_max`。
懒得量就先按 180 填 —— 映射仍然是线性的，只是"1 度"对应的实际角度略有偏差。

### 5.5 验证

串口（或 USB 虚拟串口）会打出标定表，确认烧进去的是新值：

```
 关节标定表 (改 Core/Src/arm_cfg.c):
   [0] J1 底座  0~180 deg  home 90  830~2160 us
   [1] J2 大臂  0~180 deg  home 90  600~2400 us
   ...
```

## 6. 常见改动：该动哪一行

| 我想… | 改哪里 |
|---|---|
| 换一个关节的行程范围 | `arm_cfg.c` 里那个关节的 `deg_min` / `deg_max` |
| 关节装反了（角度大反而往下） | 把该关节的 `us_at_deg_min` 和 `us_at_deg_max` **对调**，代码不用改 |
| 夹爪只开 60° | 已经是了：J4 的 `deg_min=0, deg_max=60` |
| 上电位置改到别处 | 改该关节的 `deg_home` |
| 整体再保守一点，怕烧舵机 | 调 `arm_cfg.h` 的 `SERVO_US_SAFE_MIN/MAX`（比如 700/2300） |
| 把 PWM 改成 333Hz（数字舵机） | **不行**。这是模拟 SG90，必须 50Hz。改 PSC/ARR 还要同步 `.ioc` |
| 加第五个舵机 | F103C8 只有 TIM1~TIM4；TIM2 已占满 4 通道，得用 TIM3 或 TIM4（见 `.ioc` 里 TIM3 现在是 1ms 时基） |

## 7. 怎么确认它真的对了（验收自查）

| 任务书 T1 要求 | 怎么证明 |
|---|---|
| 四路独立输出 50Hz | 四路 CCR 可以给不同值，各自独立；周期由 ARR 固定为 20ms |
| 脉宽覆盖 500～2500µs | 安全窗是 600~2400，覆盖了任务书要求的有效区间；改 `SERVO_US_SAFE_*` 可放开到 500/2500 |
| 步进 ≤ 2µs | 0.5µs/计数，`ARM_PWM_TICKS_PER_US = 2` |
| 角度→脉宽线性 | `arm_deg_to_us()` 里那一行插值公式，参数全在 `arm_cfg.c` |
| 参数不散落 | 搜一下 `500`、`2400` 这类数字，只应出现在 `arm_cfg.h` / `arm_cfg.c` |

没有示波器时，最硬的证据是**舵机自己的行为**：给 90° 应该在中位，给 0° 和 180° 应该各自到端点且不异响。
把 `arm_set_deg(j, 0/45/90/135/180)` 打点，看动作是否等间距 —— 等间距就说明线性映射成立。

## 8. 踩过的坑（都在这份代码里避掉了）

1. **CH2/CH3/CH4 的 `Pulse = 0`** — CubeMX 只给 CH1 写了 3000，另外三路是 0。
   `arm_init()` 里先统一写中位再启动，就是为了堵这个。
2. **`us_at_deg_max < us_at_deg_min` 时用 `uint16` 相减会下溢** —
   所以换成 `int32_t span_us` 再算。这是"装反的关节"最容易炸的地方。
3. **`deg_max == deg_min` 会除零** — 加了 `span_deg == 0` 的保护。
4. **改 PSC/ARR 忘了同步 `.ioc`** — `arm_cfg.h` 顶部写了警告。
5. **用 `%f` 打印浮点** — newlib-nano 不支持，会静默输出空。
   banner 里所有数都是整数。
6. **USB 和 UART 同时打印时卡死** — `log_flush()` 里 UART 用 50ms 超时、
   USB 用 30ms 超时且只在 `USBD_STATE_CONFIGURED` 后才发，任何一路没接都不会阻塞主循环。
